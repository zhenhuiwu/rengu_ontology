# 对象实例只读绑定

默认关闭。导入/发布对象定义不会自动连接数据源，也不会开启实例读取。零售本体1保留原受控绑定；其他本体不能按同名对象借用它。

部署人员显式设置 `RENGU_OBJECT_READ_ENABLED=1`，并将 `RENGU_OBJECT_READ_BINDINGS` 指向仅部署人员可维护的 UTF-8 JSON 文件。文件根为数组，每项结构如下（占位符需换为实际已发布定义，不是初始化数据）：

```json
[
  {
    "ontologyId": 2,
    "objectType": "<对象编号>",
    "datasourceId": "<当前本体的数据源编号>",
    "schema": "<实际schema>",
    "table": "<实际表>",
    "columns": ["<获准读取列>", "<单列主键列>"],
    "urlEnv": "RENGU_OBJECT_READ_URL_DOMAIN"
  }
]
```

`urlEnv` 指向独立只读 PostgreSQL/金仓连接 URL 环境变量；不要把 URL、密码写进绑定文件、文档或浏览器。只接受 `postgresql+asyncpg`。URL 的主机、端口、数据库须与当前本体中登记的数据源相同；允许使用不同的专用只读账号。源库账号只授予对应表 SELECT。连接启动强制只读、连接超时和语句超时，每次请求在同一只读事务中计数/分页/分面，不执行用户 SQL。

每次源事务在业务查询前确认账号不是超级用户、没有 `BYPASSRLS` 且事务只读；写入受信的当前 `rengu.ontology_id` 事务 GUC，保留同库表已有 RLS 边界。检查失败则不读取业务表；不会自动赋角色、改策略或退回主库账号。

绑定同时核对工作空间、对象、数据源编号和已发布来源映射；属性仅接受定义中的直接源列，并须落在 `columns` 白名单，主键须有真实单列映射。不接受表达式、转换或任意表名。缺少配置/映射时返回未绑定；配置不合法、读取失败时明确报错。不会自动配置或测试外部连接。

所有读取叠加当前身份/预览身份的对象行权限。未知字段、未实现的跨对象权限关系拒绝读取；未授予对象权限返回空范围，不能借来源数据源扩大权限。平台元数据仍通过原会话的工作空间 RLS 读取。

使用区目录/元数据、单个对象和关联读取允许 `object-search:view` 或 `object-detail:view` 任一既有页面权限；两者都没有则拒绝。实例搜索、导出及批量提问仍要求搜索权限，单个对象提问允许任一；预览身份同样校验。真实对象元数据从使用区专属接口读取，不要求构建区的对象/关系查看权。字段及对象行权限始终保留。

隐藏/敏感属性不返回值、不参与关键词、分面或排序。主键属性若隐藏、敏感或未映射，整项绑定拒绝读取；标题受限时只可回退到已经公开的合法主键。导出还核对当前本体真实角色的对象 `view` 与 `export` 授权（稳定 API 名匹配），预览不可导出；单次最多10,000条，超过时拒绝并要求缩小范围，不静默截断。选中 ID 上限5,000，空数组不会变成导出全部。

搜索及关联每组默认10条后台分页；搜索、计数、筛选、排序和分面共用同一绑定与权限谓词。关联只执行所选版本已发布的单跳直接等值关系，两端连接属性须公开且已映射，并分别应用各自对象行权限；跨源、无映射或多对多中间表尚无执行定义的关系明确不可查询，不猜连接表达式。

范围提问保留既有零售规则，新增明确的“对象数量”和“属性名称/API 名 + 合计/平均值/最小值/最大值”直接汇总；仅数值且公开的映射属性可聚合，不解析任意自然语言或执行用户 SQL。汇总直接在完整授权筛选/所选 ID/当前对象范围计算，不先截取第一页或5,000个 ID。旧零售规则需要展开 ID 时，超过上限明确拒绝，不返回截断汇总。回答标明当前授权实例及未套用指标口径。

历史模式只读取指定版本的对象/属性/关系定义；物理实例是当前源库的授权记录，接口以 `dataVersion: "current"` 标记，不表示历史业务状态。历史来源映射若不再获准，不借当前映射替换。

此次只实现配置接线，不设置启用变量、不创建绑定、不连接外源、不创建实例或授权。运行验证由实际配置具备只读权限的数据源后另行进行。

前端真实模式的类型、搜索、详情及范围提问失败均展示错误，不切换演示数据。历史搜索/详情在既有标题处以“当前实例”提示，tooltip 为“按该版本定义查询当前数据”。显式 mock 模式继续保留。

可选 `backend/scripts/check_object_source.py` 仅留下纯内存断言，覆盖直接标识符、主键映射、受限属性与明确聚合标签；交付时未执行。仅允许 AST/前端 typecheck，不运行后台、集成、迁移或外源测试。

交付核查：前端 `npm run typecheck`、6个相关 Python 文件 AST 与限定差异空白检查通过。尚未实际验证外部源读取、聚合或导出，不将配置接线声称为跨源实测。可在保留零售本体1中查看 `/use/objects/search?ontology=1&type=store`、进入详情与关联页签，再在范围提问中选择“对象数量”；空本体2仍应显示空目录，显式同名深链不得借用零售记录。实际界面与读取证据由主代理继续核查，不创建记录或修改授权。

## 旧对象接口边界收口

- 旧 O2/O3 搜索、导出委托同一 `explore_search` / `explore_export`；O5 详情只以公开投影及对应版本属性组装兼容外壳，去除硬编码附带字段和衍生 KPI；O6 关联委托已发布真实关系分页；O7 时间线只展示同版本公开映射的日期/时间字段，不拼入隐藏的渠道、仓库等说明。O9 的空动作目录也只用公共投影检查对象存在，不新增动作能力。
- 旧 `facets` 的键及返回 `cells` 使用真实属性 API 名，无法对应的旧零售别名明确拒绝，不猜别名。旧“同城门店”“订单商品”等硬编码推断分组不再冒充已发布关系，关联 `group` 使用真实关系编号，返回 `state` 说明不可查询状态。历史接口统一用该版本定义查询当前授权实例；公开主键不满足时同样拒绝读取。
- 旧零售范围汇总保留原支持的问题，但只在原受控零售绑定及所需公开字段齐备时执行，过滤范围也经同一 Bound 校验；不因存在同名对象或新来源而借用旧零售 Data。新旧 CSV 共用现有 `admin.exports.csv_cell` 处理表头和所有单元格，CSV 引号不作为公式防护。
- 主代理已实际通过新 API 验证：零售1订单数量1,286、门店95；HF0004关联总数121，翻到第二页仍10条；工作空间2对象与动作均空，无零售串用。这些证据不代表旧兼容路由、CSV 下载或外源执行已经实测。本次收口未运行后台测试、旧接口 HTTP、业务写入或外部连接。
