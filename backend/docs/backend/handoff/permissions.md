# 数据库功能权限与行级范围

功能权限只从启用用户的真实 `SysRoleMember` 关联聚合：`none < view < manage`，跨角色取最高值。
配置中的本体管理员标志不能绕过功能权限。未知/停用用户返回 401；权限不足返回 403。

已有各模块路由的 `require_func` 映射从本提交开始实际执行。CR 写入不再仅凭 `releases:manage` 放行：

- CR 路由要求 `releases:view`；新建无目标空单另须 `releases:manage`。
- 新建带目标、加入、保存、放弃目标，分别要求该目标定义页面的 `manage`。
- 改单头、校验、提交、审核、撤回、重新打开及删除，要求整单全部目标页面的 `manage`。
- 目标并集包含 `CrTarget`、`CrItem` 与旧 `detail.touches`；未知目标拒绝授权。
- 整版发布与回滚在服务层再次检查 `releases:manage`；发布保留已有本体管理员限制。
- 已有 owner/reviewer 状态机与只读拒绝规则保持。

行级权限在身份解析时一次加载实际对象授权/范围。无授权、未知或不唯一身份映射为 `DENY_ALL`；
仅有实际不受限授权时返回 `None`。范围按已有 SQL 白名单与跨角色 OR 规则合并。

此补丁不包含新增目录、审核人选择器、表单、分页、trial/analysis 或新业务执行器；没有数据库迁移。
专项回归覆盖真实角色撤销、目标页/整单权限、服务层发布防绕过及 SQL 行范围继承。
历史测试的角色/静态身份夹具需按测试意图显式授权，不得把全局行过滤器替换为 `None`。
