# 保留现有数据重新同步操作说明

适用范围：已经部署了带“数据同步”功能的版本，且数据源是达梦 DM8。本文不要求删除或重建数据源、对象、指标，不要求清库、重新导入 SQL 或执行 seed。远端电脑是否已具备该功能，需要在远端界面确认。

## 同步会改变什么

“从头同步”从已保存的源表和已授权字段开始重新读取，按主键分批写入平台的同步镜像。它**不会写入或删除达梦源数据，也不会删除本体中的对象、指标、函数、字典和业务知识**。已有镜像行会按源数据当前值更新；源端新增的行会加入镜像，源端已经删除的旧行不会被自动删除。因而它适合刷新数据，但不能保证镜像每一行保持原值。

同步期间，相关对象可能暂时无法通过问数读取；分批处理中看到的是已完成批次的结果，并不表示全部数据已经读完。若同步失败，已完成的批次保留，失败原因会在界面显示。如果完全不能接受镜像内容变化，请先备份目标机平台数据库，再决定是否同步。

## 操作步骤

1. 在顶部选择包含原有对象的正确本体，进入 **构建 → 数据接入 → 数据连接**，从左侧选择原有的达梦连接。不要删除或重建连接。
2. 点击 **测试连接**，确认连接成功。再进入 **库表**，找到需要的数据表，核对“映射对象类型”显示的是原有对象。字段勾选只是读取授权；它本身不等于已映射对象或已同步。不要为排查错误随意更改 Schema、表、主键或授权字段。
3. 点击 **同步计划**。在 **数据同步** 区域找到对应对象。若没有该区域或对象，请先确认当前页面和本体、表与对象的映射及其已保存的只读授权；不要删除原有定义。若界面根本没有该功能，可能是旧版本，仅靠旧界面无法完成本操作；管理员应先检查部署版本，并按 [保留数据升级说明](upgrade-retain-data-2026-10-30.md) 备份和评估原地升级。
4. 在对象行输入每批条数，建议先用界面默认值 **100**。同步没有完成、且按钮显示 **继续下一批** 时，先点击它；同步已完成或尚未开始时，点击 **从头同步**。等待状态从排队或同步中变为 **本批完成**。不要连续重复点击，也不要在运行中关闭服务。
5. 如果尚未显示 **已读完当前范围**，等待本批完成后继续点击 **继续下一批**，直到出现该提示。**已处理**是本轮从头开始累计处理的数量；**镜像**是当前保留的镜像行数量，可能含源端已删除的旧行，二者不一定相等。点击 **运行记录** 可查看每批状态和读取/写入数量；写入数量是处理的行数，不等于实际发生变化的行数。
6. 到 **使用 → 对象 → 对象搜索**确认当前本体对象可读取，再在智能问数中重新提问。如果提示“不允许查询表”，记下提示中的表名：同步不会自动放开任意表，还需要核对该表是否对应当前本体中已授权、已同步的对象，以及远端使用的前后端版本。不要关闭只读检查或跨本体授权。

如果 **测试连接**失败，先解决真实连接或账号问题；如果显示 **配置已变更，请从头同步**，先核实是哪些来源或对象配置发生变化。更改数据源、表、字段授权、主键或对象属性会使此前镜像不再匹配当前配置，不能靠旧镜像冒充新配置的数据；不要为了消除提示盲目调整这些设置。

不同数据库可能保留不同的表名或字段名大小写。新版本将外部镜像提供给问数的逻辑表名统一为小写下划线形式，例如 `PltPlatform` 对应 `plt_platform`；对象 API 名和源数据库表名保持原样。旧逻辑名仅在当前本体已登记的别名能唯一对应时兼容，带引号的旧名须精确匹配；名称冲突不会自动猜测。对于仍不能匹配的表，问数最多依据当前本体可查看的受控表和字段重新生成一次，仍失败则提示原因并停止，不会放宽授权。此修正不改已有数据或镜像，不要求重同步；远端需要部署包含该修复的版本才能生效。

## 管理员可选：接口契约

只在确认当前部署版本支持且已有适当权限时使用。请求必须携带该部署的正常身份以及当前工作空间的 `X-Ontology-Id`，不要在聊天、日志或共享脚本中记录令牌、密码、源地址或业务数据：

- 查询状态：`GET /api/data/v1/external-read-bindings/{对象编号}/mirror`
- 从头提交一批：`POST /api/data/v1/external-read-bindings/{对象编号}/mirror`，请求体 `{"maxRows":100,"restart":true}`。
- 本批完成且 `complete` 为 `false` 后，继续一批使用相同接口，请求体 `{"maxRows":100,"restart":false}`。一次最多 1000 行；错误或状态异常时停止并查看原因，不要无限重试。
- 查询运行记录：`GET /api/data/v1/external-read-bindings/{对象编号}/mirror/runs?page=1&size=10`。

接口提交后返回排队状态；应轮询状态接口并等待 `succeeded` 或 `failed`，不能把提交成功当作同步完成。该接口的 `restart` 重置进度，不删除已有镜像行；若已修改绑定，原签名下的数据可能暂不可见，直到相应行按新配置重新同步。旧部署如果没有这些接口，不能用以上地址假定同步成功。

本文根据当前工作区代码核对；尚未在您的远端电脑执行同步或验证其版本与数据。
