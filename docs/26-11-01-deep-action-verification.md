## 真实阻断：已暂存动作被前端误判为其他记录

主代理现场：空白工作空间 16 的办公设备巡检动作 `recordInspection`，设备 16001、巡检得分 90，问数校验通过；点击确认并执行后，暂存记录 `ACT-20261101-0001` 返回待确认，但卡片提示类型、目标、参数或告警不一致并阻止提交。

源码根因是参数表示不一致，而非已证实的跨工作空间缓存污染：

- `backend/app/modules/qa/intent.py` 的 `_params_text` 把结构化参数转换为显示摘要 `score=90`，`action_snapshot` 将摘要放入 `stage.params`，同时在 `action.params` 保留原始字典。
- `backend/app/modules/qa/router.py` 的 `stage_turn_action` 从服务端保存的 `card.params` 生成 JSON 字符串；对返回记录的类型、对象、参数、告警逐项严格核验后才返回。
- `frontend/src/pages/qa/Workbench.vue` 的 `matchesAction` 原来把运行记录的 JSON 参数与 `stage.params` 摘要比较。`normalizedParams` 无法把 `score=90` 解析为 JSON，因此正常返回的 `{"score":90}` 被误判。

修复为优先比较 `action.params` 的结构化 JSON，与暂存端点使用相同字段；只有缺少结构化参数的历史卡片才回退 `stage.params`。类型、对象类型、对象编号、告警和参数内容仍严格比较；没有按名称宽松匹配，没有绕过原记录身份检查，没有重新发起或自动执行。

离线校验：`node frontend/scripts/check-qa-inline-action.mjs`（在 frontend 目录执行时为 `node scripts/check-qa-inline-action.mjs`）通过，包含原有暂存/恢复/轮询/上下文切换/确认守卫与 SFC 编译；新增断言证明结构化 score=90 与返回 JSON 一致时通过，结构化 score 不一致时即便摘要相同也拒绝。
