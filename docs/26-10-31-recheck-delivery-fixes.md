## 核对到的现有行为

- `delivery.py` 已将自动等待限定为 `EVENT_OBJECT_NOT_SYNCED` 与 `ORDERING_PREDECESSOR_UNRESOLVED`，按真实运行时钟最多等待创建后 15 分钟，不增加外部尝试次数。
- 权限、身份、配置等错误已进入 `failed`；历史 pending 若携带此类错误，调度前先终止自动重放。修复权限或路由本身不会自动重放这些历史失败。
- HTTP 自动重试已在同一投递行、同一幂等键上执行，预算由现有 `retry_budget` 限制到最多 5 次重试（默认 3 次），仅对现有策略认可的网络错误、429、5xx重试。2xx ACK 才算传输成功。

## 本轮实际修改

### 有界自动重试

- 自动重试必须有对应当前实际尝试的 `attempt_started` 日志，计数必须为有效整数并处于预算内。历史日志缺失、损坏、计数为布尔/字符串或对应错误尝试时，转 `HTTP_RETRY_HISTORY_INVALID_REQUIRES_REVIEW`，不能将计数重置为 1。
- 如果 HTTP 重试之间又进入对象同步/前序等待，继续沿用上一轮自动重试计数及路由指纹，避免一次临时等待重置重试预算；路由指纹变化时须人工核查。
- 只有最近明确记录的人工 `retry`/`supplement` 处置才能开始新的自动重试预算。已经尝试过却没有原因、也没有有效人工重新排队证据的 pending 不会盲目重放。
- `discover()` 发现无法解析订阅或订阅名称非法/重复的非空历史快照时，将事件标记为失败并写明须人工核查，避免同一批无效事件不断占据扫描前 200 个名额。不会为其推测订阅或构造可执行记录。空快照仍维持原隔离边界，不补造业务记录。
- 补充订阅快照类型与归属检查，避免历史异常订阅在 `.get()` 处反复崩溃而始终 pending。真正未尝试且快照有效的新 pending 仍走现有正常投递流程，不按年龄批量跳过。

### 结构化错误证据

- 在现有追加式 `EventDeliveryRecord.detail.errorDetails` 中保留预检/执行阶段的通用错误诊断，不新增数据库列或迁移。
- 异常明细 API 通过顶层 `errorDetails` 返回当前尝试与当前错误对应的最近证据；历史记录仍在原分页中保留该结构。
- 结构包含错误码、阶段、可选 HTTP 风格错误状态、失败字段/校验项的索引、可安全显示的字段路径/校验项名称、总条数。每类最多返回 20 条，并标记 `valuesOmitted: true`。
- 不保存异常自由文本、`message`、`fail`、`input`、URL、敏感标签或任意嵌套 details。这些内容可能拼接真实状态、参数、载荷或凭据；诊断理由使用固定码，未复制原始值。非标准异常文本使用固定 `DELIVERY_PRECONDITION_UNAVAILABLE` 代替错误码。
- `safe_result()` 对损坏的非对象历史 result 返回空，避免错误展示本身导致新的重复扫描异常。

仅用于说明的通用 API 样例：

```json
{
  "code": "VALIDATION_FAILED",
  "phase": "execution",
  "status": 422,
  "valuesOmitted": true,
  "fieldsCount": 1,
  "fields": [{"index": 0, "field": "params.value", "reason": "FIELD_VALIDATION_FAILED"}],
  "failedCount": 1,
  "failed": [{"index": 0, "name": "对象状态校验", "reason": "SUBMISSION_CRITERION_FAILED"}]
}
```

字段/名称不可安全显示时仅保留索引；来源未提供结构化 details 时仅保留通用错误元信息。历史上已经丢失的 details 无法从错误码恢复，本次没有推测或回填。
