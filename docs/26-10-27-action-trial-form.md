# 动作类型试运行输入 · 2026-10-27

入口：`/build/ontology/action-types` 选中一个已发布动作，或该动作的已保存变更单草稿，点击右上“试运行”。显式 mock 模式保留原确认卡、示例值与通过提示；以下说明针对真实 API。

## 输入和定义

- 局部 `ActionTrialForm.vue` 复用现有 Ant Design 表单、数字输入、日期选择、文本和列表控件。仅懒加载选中动作的完整参数定义；草稿先读取真实 CR 及该动作已保存行，用现有 `draftRows/draftFields` 叠加新增、修改、删除。未保存草稿继续禁用试运行。
- 字符串、枚举、文本、整数、数值、布尔、日期、日期时间、枚举列表及对象引用/列表按真实类型输入。必填、整数、有限数值、布尔与列表做本地基本检查；完整参数规则与条件仍交给真实 checker。
- 定义中的默认值可能是“当前告警”“上一个合法状态”等说明，不作为实际参数自动提交。枚举没有结构化候选时提供文本输入，不猜候选；参数原有校验说明显示在对应输入下。
- 目标对象类型取动作真实 `targetKind`（草稿可覆盖）；用户不能改选另一类型。对象引用参数按引用类型查唯一已发布静态对象类型；目标和引用对象走现有受控 `exploreSearch`，告警走真实 `listAlerts`。均只请求当前10条，支持关键词及后台分页，不使用演示对象、不遍历全表生成候选。没有真实权限、唯一类型或数据绑定时显示真实错误。
- 目标对象上下文和动作引用参数独立提交，填写“订单状态修正”时可将同一真实订单分别选为目标对象与 `order` 参数。可选告警引用继续由 checker 在唯一值时解析告警上下文。

## 只读契约和结果

`POST /action-types/{id}:dry-run` 原参数契约外仅增加 checker 原有的可选 `objKind/objId/alertId` 上下文字段，字符串限制1–64字符且不含NUL。目标类型和编号须同时提供，类型必须匹配所选动作实际定义；checker 自行读取真实用户行权限和已发布非敏感属性，告警仍要求真实权限和当前处理人。未增加业务字段、数据库结构、审批、排队或执行入口。

历史仍携带 `ver` 并沿原 history 守卫校验；预览身份继续禁止试运行。动作、身份、历史版本、草稿视图/CR 切换会销毁旧表单和结果，迟到响应不回填。关闭后在相同上下文重开保留输入；每次重开重新读取已保存定义，定义变化清掉旧输入/结果。

通过、不通过及请求错误均在可关闭弹窗中显示；全部失败原因及本次提交输入可展开查看，同动作上下文保留“查看校验结果”入口。失败不清空输入，输入变化后将上次结果标为需重新校验。结果仅驻留当前页面上下文，刷新后不保留，不产生数据库试运行记录。

参数页切类型/请求期间显示“参数加载中…”及表格加载状态，避免把未返回结果显示为0个参数。

## 真实填表反馈后的绑定修正

协调者使用真实订单同时填写目标和 `order` 参数，提供目标状态与修正原因，确认请求带 `objKind/objId`，字段与 checker 期望一致。初次返回的“原因必填”“订单状态”缺上下文来自已有表达式与定义名不一致，而非前端遗漏对象：`参数.原因` 对应已声明 `修正原因/reason`，`订单.状态` 对应真实受控 `订单状态/status`。

checker 仅为这两个既有词汇补唯一明确别名。原因别名参与参数名字冲突计数；状态别名只来自 API 和 backing_column 均为 `status` 的已发布非敏感可见属性，且没有其他同名属性。原行权限、真实对象唯一性和受控表/列检查全部保留。缺上下文时现在指出具体 `类型.字段`。

`枚举` 参数的明确 `值 / 值` 声明集合可直接核验（2–32项，每项1–128个字母、数字、下划线或连字符）；不把自然语言规则猜作枚举。“系统同步乱序 / 人工误操作 / 其他”属于此集合。

明确规则“必须是生命周期 v4 中的合法迁移”按受控上下文实际 `status` 和实际 `targetStatus` 求状态对。复用与 SM-ORD 相同的公开 `app.contracts.rules.lifecycle_transition_pairs`，严格检查指定版本、完整状态和迁移引用。当前视图绑定最新真实发布快照，历史视图绑定指定发布快照，且必须有同版本动作定义和一致对象API；缺版不借用其他版。迁移对不存在返回“迁移未匹配”，定义缺失/无法求值返回“参数规则不可校验”。这里只校验已发布迁移集合，不执行迁移、guard、effect或动作副作用。

现有显式集合 `当前用户.角色 ∈ {订单运营组, 规则 SM-ORD}` 区分正式角色和规则来源。正式角色只按真实 `SysRole.code/name` 精确查证，再与该用户真实有效角色成员比较；未登记的名字明确列出，不能用“系统管理员”等其他角色替代。“规则 SM-ORD”不作为人角色、不授予旁路，本试运行没有可信规则来源时不匹配此分支。其他自由文本不推断；“条件未匹配”与“条件不可校验”分开呈现。

共享 checker 额外拒绝同目标类型的单对象引用与 `objKind/objId` 不一致。此前真实执行只验证目标行权限，单独的 `order` 参数仅检查字符串类型，存在用有权目标A携带其他订单B的参数漏洞；现在试运行、暂存/提交及执行前复验均通过同一检查拒绝。匹配依据为动作明确目标类型名/API/code，不从自然语言默认值推断对象。目标对象的真实行权限仍由已有提交/执行授权检查负责，没有新增业务动作或角色。

## 核验范围

提供 `frontend/scripts/check-action-trial-form.mjs`，直接加载组件实际脚本验证必填、0/false、整数拒绝、上下文透传及请求失败保留输入；没有后台或数据库依赖。本轮不运行后台测试、pytest、集成/迁移测试、构建或长回归。真实前端填写、校验、身份/版本切换及错误交互由协调者统一实际操作；本文不声明这些操作已通过。
