## 权限与真实数据限制

- 本轮沿用平台已有多本体 RLS 和真实成员/功能/对象行权限；仅使用 `rengu_ontology`，保留既有记录，不动 `auto_ontology`。本轮三组不新增表或迁移，不重置 seed、不复制零售实例或补权。
- 对象专用连接只从部署侧受信环境取得，精确核对登记来源，事务确认非超级用户、无 BYPASSRLS、只读及超时，并设置可信本体 GUC。未知行权限字段/关系拒绝；隐藏或敏感字段不作为新读取入口的结果、筛选、分面或排序，公开主键不能确认时拒绝实例读取。没有启用或配置任何外部源，本轮不验证真实外部连接。
- 对象历史模式取所选发布的定义，实例仍是当前源的授权记录，明确标为当前实例；不能称为恢复历史业务状态。跨源关系、多对多中间表及缺映射的关系不猜连接式。
- 页面源仅接受服务端真实成功查询及明确发布依据。非 seed 的旧成功回答若已有 SQL、发布 ID 与版本，可重新校验后重读；没有依据的旧回答/模板仍不可执行，不能为了验收伪造 SQL 或语义计划。SQL 原条件不做日期/范围字符串替换，不能只换筛选标签。
- 页面执行限制为最多 20 张明确表格卡，整页共用现有查询总超时；单卡最多 200 行且标记截断。发布、公开字段或当前权限不兼容时不返回旧缓存；刷新全部成功才整体替换，失败保留原缓存与时间，但保留不等于仍可向失去权限的身份展示。页面 CSV 明示有界结果，不称全量。
- 共享决定页面可见性，不授予数据权限。预览身份需真实 `roles:manage`，历史/预览不能写页面；对象及页面导出另外检查真实对象导出授权。元数据 API 密钥不因共享获得业务数据读取或执行权限。
- 告警转派、动作确认/审批/重提/对账均需当前权限与完整引用核验；不自动转交审批、清理历史或改变旧记录。旧摘要不能验证对象引用时隐藏参数、日志和外部原因，不输出不受控旧内容。
- 自动刷新调度、外部订阅、任意自然语言范围分析和跨领域通用业务执行器不在本轮闭环内。Composer 对象引用未扩展。ERP、Kafka、真实预测模型与模型提分评测按原约定后置。
