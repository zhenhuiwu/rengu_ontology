# 外部动作联调修复记录（2026-10-31）

本次外部动作实现保留工作区既有未提交成果，未连接报告中的远程数据库或外部系统，未执行动作、探测、发布、构建或打包。后续主会话获授权的本机0048增量及只读UI核查见[统一说明](26-10-31-deployment-integration-fixes.md)，不代表真实动作联调通过。报告中的凭据和请求值未写入代码或本文档。

## 授权与版本诊断

`submit_adapter` 先识别显式动作授权，再取得部署适配器。动作发版不会自动把旧版本授权提升至新版本，也不会修改外部系统授权记录。

| 情况 | HTTP / code | 恢复方式 |
| --- | --- | --- |
| 当前动作没有执行授权 | 403 `ACTION_EXECUTOR_NOT_AUTHORIZED` | 在外部系统“动作授权”中选择已发布动作及允许路径；部署名单模式需管理员配置 |
| 授权版本与动作定义版本不同 | 409 `ACTION_EXECUTOR_AUTHORIZATION_VERSION_MISMATCH` | 核对已授权版本和当前动作版本，明确更新该动作授权后保存 |
| 授权路径不在部署名单，或与目录选择不一致 | 409 `ACTION_EXECUTOR_AUTHORIZATION_PATH_MISMATCH` | 核对部署允许路径及所选目录，再手动修改授权 |
| 执行记录绑定版本与当前动作版本不同 | 409 `ACTION_DEFINITION_VERSION_MISMATCH` | 按当前版本重新暂存并确认，旧记录不能替换定义执行 |
| 执行器未配置或不可用 | 503 `ACTION_EXECUTOR_UNAVAILABLE` | 修复部署配置，不放宽授权 |

授权版本错误返回 `expectedVersion`、`authorizedVersion`、`currentVersion`；记录版本错误返回记录所需的 `expectedVersion` 和当前 `currentVersion`。外部系统页面显示旧授权版本，并提供显式“更新授权至当前版本”操作；选择路径本身不再悄悄提升授权版本。

部署白名单、系统身份、接口路径、动作版本、`Idempotency-Key`、签名及已持久排队后配置比对仍然生效。没有自动重发业务写入。

## 接口目录诊断

新增 `require_selected_endpoint` 用于写回配置、发布校验及执行阶段。原 `selected_endpoint` 保留失败返回 `None` 的兼容契约。

| code 后缀（统一前缀 `ACTION_HTTP_ENDPOINT_`） | HTTP | 定位字段 |
| --- | --- | --- |
| `NOT_FOUND` | 409 | `httpEndpointId`，目录项不存在或不唯一 |
| `CATALOG_INVALID` | 409 | `httpEndpointId`，保存的目录项本身无效 |
| `FORMAT_INVALID` | 409 | `endpoint`，方法及规范路径格式不符 |
| `CHANGED` | 409 | `httpEndpointId` / `endpoint`，用途、方法或路径变化 |
| `PARAM_UNDEFINED` | 422 | `httpMapping.request.<索引>.source`，引用参数不在动作定义中 |
| `MAPPING_CHANGED` | 409 | 对应 `httpMapping` 字段路径，目录与动作映射不同 |

错误消息列出前几个字段位置，`details.fields` 保留结构化位置；不会返回映射常量、动作请求参数值或响应值。发布阻断的 actionTypes issue 同时保留上述 code 和 details。修复时核对动作参数，再从目录重新选择接口并发布，不通过重试执行绕过校验。

## 同路径多动作与锁版本

接口目录继续要求编号唯一、总数最多 32、探测接口最多一个；取消动作路径全局唯一限制。不同目录编号可以使用同一方法和路径，并各自保存映射；动作通过 `httpEndpointId` 选择具体契约。现有目录也可被多个动作复用。关联动作显示优先按目录编号匹配，旧动作保留按方法和路径匹配的展示兼容。

这不是增加任意目标访问能力：执行仍要求每个动作的版本和授权路径通过既有适配器名单，方法来自所选目录，幂等键仍按执行记录产生。`probe_path` 仍为单一字段，因此本次不扩展为多个探测入口。

`GET /ext-systems/{code}` 详情补充 `lockVersion`，原授权、目录、探测配置接口的 `version` 保留不变。关联动作额外返回可空的 `httpEndpointId`，保持既有字段兼容。

## 镜像身份与物理写入边界

本次消费镜像修复的 `row_identity`、`scope_column` 和 `row_identity_column` 契约：`action_edits.existing_row` 及动作条件读取不再把业务字段 `id` 当成物理行编号，也不把镜像业务字段 `ontology_id` 当作用域字段。HTTP 对象字段读取沿用受控属性、对象授权、行权限和敏感属性检查，外部镜像属性按 `source_column` 解析。

外部镜像只供读取。结构化本地属性编辑和本地关联写入在 `source_sql` 镜像绑定处明确拒绝；由外部动作承担的声明效果仍经已授权 HTTP 通道执行。HTTP 成功不能替代源库与镜像的一致性核对；此修复没有实现同步回写或让本地镜像更新冒充源库更新。镜像读取与物理源库的即时一致性不在本次代码验证范围内。

## 策略字段兼容

`limits.dailyLimit` 作为 `dailyCount` 输入别名，内部及输出继续使用 `dailyCount`。二者同时传入且值不同会拒绝；相同值允许。前端策略编辑器同步接受别名，修改“每日总限额”后规范为 `dailyCount`。`perMinute` 仍拒绝，没有伪造每分钟限流支持。

## 第二阶段：镜像同步界面

改动仅涉及 `Connections.vue`、`ExternalReadBindingModal.vue` 和 `api/datasources.ts`。实现前已与镜像后端负责人核对字段和取消接口。

- 手动提交是整个扫描任务，界面不再要求用户每 100 行点“下一批”；批量输入只控制每批行数，任务自动逐批运行。
- `complete=false` 一律展示尚未完整，历史遗留的 `succeeded + complete=false` 也显示“未完成”。处理行数与当前签名镜像行数分别展示，不把存储行数当作源表总数，也不显示虚假的完成百分比。
- 新任务显示“同步数据”；已完整扫描后普通更新显示“更新镜像”；后端允许恢复的失败或取消任务显示“继续同步”，发送 `restart=false`；不可恢复或配置变更时显示“重新同步”，发送 `restart=true`。重新扫描执行 upsert，物理保留镜像历史，不要求为普通源数据修改解除绑定或重新导入对象。完整扫描成功后才核对源删除并调整可见记录，部分同步不宣称已对齐。
- `queued/running` 时禁用重复提交，提供“取消同步”。取消在批次提交边界生效，保留已完成的数据。没有自动点击同步、取消或启用调度。
- 主行显示安全的失败原因、需核对配置提示、`processed/currentStored`。一个对象的状态读取失败不会阻断其他对象，也不会显示为未同步或允许盲目重新开始。
- `dataUpdatedAt` 是最近非空成功批次的镜像写入时间；`dataCheckedAt` 是最近成功读取源批次的核验时间，含空结果。二者来自后端实际 UTC，排队、取消、失败不会冒充数据更新。`updatedAt` 仅在详情标为“状态更新时间”，与最近任务结束时间分开。
- “详情与记录”中显示任务编号、批量、历史保留行以及源配置和结构指纹；主界面不堆叠这些技术字段。
- 读取授权弹窗显示镜像完整性与源数据核验时间，过滤已经不可用的原授权字段。未修改授权时保存直接关闭，不为普通数据刷新重写绑定。异步结果按本体、对象和请求序号隔离。

布局沿用现有组件与色彩：同步区域独立滚动，操作区可换行，长错误和指纹可断行。没有使用 Chrome 102 之后才支持的 CSS 特性，没有新增说明横幅。

### 完整扫描与源删除核对的最后补充

后端随后新增 0048 迁移字段 `last_seen_scan/is_current`：物理历史仍保留，只有完整扫描成功的末批事务才排除本扫描未见的旧记录；中断、失败或取消不提交该删除可见性变化。该迁移本次未由本代理执行。

界面同步接受可选的 `deletionsAligned` 和 `dataPublishedAt`。`complete=true` 且 `deletionsAligned=true` 才显示“本轮已完成”；旧数据只有 `complete=true`、而删除核对为 false 或老 API 未返回字段时，显示“扫描完成 · 删除待核对”。详情“删除核对”显示“已完成 / 待完整同步”；“完整扫描发布”显示成功发布可见性的实际时间，和最近非空批次写入、源批次核验、状态更新时间分别展示。读取授权弹窗使用相同的完整性判断，不新增横幅或主动源库校验。

由于这次新增了 API 字段和渲染逻辑，在初版通过后针对补充代码再执行第二次 `npm run typecheck`，退出码为 0；这是两个不同代码状态的检查，没有为未改代码重复检查。两次都仅进行静态类型检查，不构建、不启动应用或 worker、不执行真实同步。

### 官方 IAB 只读验收入口

在已选本体内进入 `/build/data/connections?ontology=<当前本体>&ds=<达梦连接编号>&tab=sync`，或点“数据连接”→达梦连接→“同步计划”。可定位 `.cn-mirror-row` 检查状态、处理行数和当前镜像行数；“刷新状态”只读取本地状态；“详情与记录”打开运行记录和数据/状态时间明细。按钮准确名称包括“同步数据”“更新镜像”“继续同步”“重新同步”“取消同步”“核对读取授权”。

本轮只读验收只打开“同步计划”“刷新状态”“详情与记录”，不点击同步、取消、测试连接或读取授权。尤其原读取授权 GET 会通过 `external_binding_context → inspect_source` 实际连接源库，因此打开“核对读取授权”或库表中的读取授权弹窗不属于本轮允许的本地只读验收。
