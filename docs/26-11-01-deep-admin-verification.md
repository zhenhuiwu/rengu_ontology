## 一次凭证表面的实际泄露边界

首次源码复核时，`frontend/src/pages/admin/ApiKeys.vue:573` 使用普通 `<a-input :value="secret.text" readonly>`。新建与轮换都把后端返回的 `secret` 赋到同一个 `secret` ref，因此成功后原始凭证直接显示在这个表面。下列泄露事实记录修复前状态，后接本轮已完成修复。

- 列表和详情使用 `mask(key) = prefix + **** + last4`；`key_rows()` 不返回 `secret`，这两处与新建成功表面不是一回事。
- 新建成功表面没有显示/隐藏开关。点击“复制”只是写剪贴板；“我已复制并妥善保存”只是退出守卫标记，均不会掩码。
- 截图会包含明文；AX/DOM 状态可能包含普通输入框的值。最终确认点击若自动返回 UI 状态，也可能在来得及关闭前泄露。没有实际生成任何凭证来探测这个风险。
- 源码中的 `closeCreate()` 允许未保存时经“仍然关闭”退出，随后 `watch(createOpen)` 清空 ref。不能为了跳过确认谎勾“我已复制并妥善保存”。
- 正常人类使用是“复制 → 在调用方密钥管理处妥善保存 → 勾选已保存 → 完成”。本轮没有调用方密钥管理目的地，不能声称凭证已妥善保存，也不应为了验收读回剪贴板或输出 secret。
- 单纯改为 password 输入并不能仅靠源码承诺所有自动化 AX 都不输出 value，因此本轮采用 DOM 从不绑定原始 secret 的修复。

### 已完成的最小 UI 修复与离线检查

主会话明确授权后，保留现有 Ant Design input、按钮、保存确认、布局和全部后端 scope 契约，只将同一个一次性面板 input 改为 `:value="mask(secret.key)"`，补可访问名称“密钥掩码”。实际原始凭证仍仅由已有 `copySecret()` 闭包写入剪贴板，不新增明文展示或 reveal 控件。

新建/轮换确认、关闭确认和面板提示同步改为“本窗口复制”的准确语义；复制失败提示检查剪贴板权限重试并指出当前显示掩码，不再教用户手选复制掩码。未保存关闭仍需要显式“仍然关闭”，没有替用户勾选保存。

运行 `frontend` 中 `node scripts/check-api-key-copy.mjs` 通过。该既有脚本现在追加模板不绑定 `secret.text`、输入使用现有 mask、复制闭包实际传入内存假凭证而非掩码，以及剪贴板拒绝时正确提示重试的断言；继续编译实际 SFC 和覆盖既有跨空间复制/维护恢复断言。检查仅使用内存假值、假 navigator 和假 API，不发 HTTP、不读真实剪贴板、不访问凭证。

**安全取证位置：生成/轮换成功抽屉（“密钥已生成”）中的“密钥掩码”输入、下方“列表中显示为”以及复制/保存按钮。** 更新后这整个页面模板中没有 `secret.text` 绑定，因此常规页面截图与 AX 输入值只会得到 prefix/last4 掩码。前提是主会话实际加载修复后的前端；本文没有浏览器实测，也未重启或主动热加载服务。不要通过 Vue devtools、内存、请求响应 body 或剪贴板探查原始 secret，这些不是页面取证范围。

## 最小只读测试密钥的实际权限

源码路径为 `frontend/src/api/apikeys.ts` → `backend/app/modules/admin/api_keys.py::create_key` → `authenticate_key` → `backend/app/common/auth.py::bind_workspace`。

| 配置 | 源码确认及限制 |
| --- | --- |
| scopes 只选“元数据读取” | 存为 `meta:read`，只携带当前身份允许的 object-types、data-quality、metrics、dimensions、glossary、rules 的 view 上限；不能从这个 scope 获得 objects/action/events/functions 的调用权限 |
| 绑定“当前账号” | 前端取 meta 中当前用户编号；后端要求等于当前真实用户并检查所选本体成员关系，不需新建服务账号或更改角色 |
| 当前纯合成新空间 | 创建固定 `ontology_ids=[request_ontology(request)]`，不是全部空间；空间由 `X-Ontology-Id` 选择，省略默认 1。请求时还检查成员关系与 key 的空间允许列表 |
| 仅一个纯合成设备 | 不支持设备/对象编号级 meta 白名单；这个密钥可读该空间当前身份允许的全部对应元数据。只能通过让全新隔离空间仅含合成定义来收窄数据范围，不能称为设备级授权 |
| 环境“测试” | 只影响 `rg_test_` 前缀和记录标签；不是独立沙箱，不会自动隔离生产数据 |
| IP `127.0.0.1` | 入参归一化为 `/32`；运行时检查 `request.client.host`，不在该函数读取随意的 X-Forwarded-For。经过代理后的实际 host 仍须在正常调用中验证，源码不足以证明当前请求一定是这个来源 |
| 30 天 | UI 最短有限期；创建后可用维护配置再提前到期。不能选择短于 30 天的创建选项，也不要勾永不过期 |
| 配额 | 可填写每分钟/每日上限；为空不限制。配额不代替 scope/IP/空间限制 |
| 类型白名单 | 对 meta-only 应保持三个开关关闭；UI 打开动作或事件白名单又不授对应 scope 会报错。`null` 的“不限制”仅针对已授对应 scope，不会自动增加该 scope |

因此，新建该测试密钥仍是签发可访问合成空间元数据的有效凭证；不能只因为名字带 test 就在不明目的下创建。现有真实密钥与角色均不得用于这个生命周期实验。

## 生命周期按钮与维护约束

`ApiKeys.vue:491` 之后的详情 footer：非吊销状态显示“维护配置”和“吊销”；只有“有效/即将过期”显示“轮换密钥”；readonly/busy 会禁用相关入口。列表各状态提供“复制配置新建”，同单一本体 guard 才应用配置；跨、多本体、未知绑定均禁用生成。

后端管理读要求 `api-keys:view`；创建、维护、轮换、吊销要求 `api-keys:manage`。服务账号的创建/维护/轮换还要求 `roles:manage`；不要用服务账号或更改账号角色为本轮制造测试条件。

- PATCH 携带当前 `version`；过期表单冲突拒绝。名称/备注/限流配额可维护；scope、IP、有限类型集合与到期只能收窄。不能原位换身份、本体或快照，不能延期或恢复过期 key。
- 轮换携带 `version`，后端行锁检查，拒绝过期/吊销记录；只换 hash/prefix/last4/时间，保留编号、授权、身份、空间、到期。新 `secret` 与创建一样加 no-store/no-cache。
- 吊销是不可恢复操作；后续认证返回 401 是源码契约，在途已认证请求不因吊销自动取消。本轮未实际用 key 请求证明这个结论。
- 前端在维护/吊销后用新版本更新打开的详情，迟到旧 GET 不覆盖新版本；已有离线脚本覆盖竞态，本轮没有重跑，也没有人为拖慢网络做 UI 竞态验收。

## 规则已发布元数据的只读合同

新 `GET /api/ontology/v1/rules/{rule_id}/definition` 声明 `require_api_scope("meta:read")` 与 `rules:view`。`require_api_scope` 对真人会话是直通（非 key_only），因此当前已登录且有 rules:view 的用户不需要新造 Bearer。

`RuleService.published_metadata()` 只投影最新 `OntologyRelease.ver` 和 `snapshot["rules"][code]`，显式过滤可信 `require_ontology_id(session)`，按发布记录 ID 倒序 limit 1。它不重建可变 Rule，不遍历旧发布记录，不调用规则执行器。缺记录、缺规则、编号不匹配或模型校验失败统一 404，不回显原快照。

独立 `PublishedRuleMetadata`/嵌套模型仅输出声明字段；Pydantic 基类默认忽略未知字段。autoStage 不含 confirmer，映射仅 param/from；出参没有 weekly、草稿、runAsUserId、运行记录、整份快照或认证对象。机器 key 还需当前身份功能权限与签发快照交集包含 rules:view，旧 key 没有 rules 快照不会自动扩权。

**现有规则 UI 尚未消费这个新入口。** `frontend/src/api/dynamic.ts:197` 的 `getRule()` 仍请求 `/rules/{id}`；`Rules.vue:572` 的详情与 overview 还读命中、版本、动作汇总。普通“条件/触发方式/动作”页面可验证既有真人查看体验，不能证明新 `/definition` 的白名单与最新发布快照合同。

只读建议：只选已知的纯合成无执行意图规则看当前定义，不点击发起变更/保存并生效/回放/恢复/暂存/执行。若通过浏览器地址直接访问 API JSON，当前会话 cookie 可继续使用，但原生地址导航不会自动添加前端的 `X-Ontology-Id`，因此默认空间为 1；URL `?ontology=N` 不能代替请求头。禁止为了访问新合成空间手工复制 session/token。没有正常产品调用入口时，应如实留下“新 definition 端点当前 UI 未接入、真人会话契约仅源码确认”的边界，不把旧详情 UI 当作新端点验收。
