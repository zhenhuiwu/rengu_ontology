# 选表事务触发器 CDC 接入契约（2026-10-31）

这是按用户明确安装的源表事务触发器捕获变更键、持续消费私有变更日志的 CDC。正常追更只读取日志涉及的源主键，不按分钟扫描源全表。首次建立或明确重建基线仍复用既有有界分页全量扫描。原生达梦归档日志挖掘能力及当前实例限制见 [源能力记录](26-10-31-cdc-source-capabilities.md)。

## 显式安装及运行

数据源同步模式允许保存 `实时（CDC）`，保存模式本身不安装任何源对象，也不启用任何对象订阅。每个对象仍必须有已发布映射、包含源单列主键的明确只读字段绑定，以及当前工作空间所有者授权。

对象接口基址为 `/api/data/v1/external-read-bindings/{code}/cdc`：

| 接口 | 行为 |
| --- | --- |
| GET 基址 | 仅查询本地订阅状态；页面轮询不会反复连接源库 |
| POST `/probe` | 真实只读能力探测；不声称已经验证 CREATE 权限 |
| POST `/plan`，`{version}` | 核验所选源结构，生成私有 generation、明确源对象 SQL 及计划摘要；不执行源写入 |
| POST `/install`，`{version,planDigest}` | 明确安装计划中的元数据表、日志表、事务行触发器；不会自动启用消费 |
| POST `/enable`，`{version,reinitialize?,maxRows?}` | 核验捕获已安装，再明确建立基线并开始消费；数据源须已保存为 CDC 模式。复用现有批量输入，不传则沿用已有镜像批大小 |
| POST `/pause` | 暂停消费并保留源捕获及未确认日志；不会卸载触发器 |
| POST `/resume`，`{version}` | 从保留基线和精确确认批次恢复；失效状态须明确重新计划/安装及建立基线 |

`version` 固定当前只读绑定版本。安装计划不能在修改字段、源身份或读取绑定后继续复用。源 DDL 可能隐式提交，因此安装失败仍保留本地计划和错误；重复安装只核验并补齐同 generation 的受管对象，不覆盖同名未知对象。暂停或换代不会自动 drop 源对象。换代前的 capture 资源身份与精确待确认批次保存在 `cursor_value.retiredCaptures`，用于受控运维处置，不会在重建基线时抹除。

本机的原 `project`、`task` 不因新增功能自动安装捕获。真实源写入联调只允许既有专用合成表；具体安装及测试结果应以单独实测记录为准。

## 无水位跳过与恢复顺序

每个工作空间、对象、数据源及读取绑定版本固定独立 capture generation 和私有日志。其他工作空间不能确认或吞掉此订阅事件。

日志事件 ID 只标识事件，绝不作为提交顺序或最大水位。每批读取当前已提交且未确认的全部 pending 集合中的有界批次，不采用 `id > last_id`。先分配小 ID、晚提交的事务仍会在后续 pending 查询中出现。源事务整体或保存点回滚应同时撤销相应触发器日志；该行为仍需真实源测试证明。

每个事件提供旧键和新键；消费者重读这些键的当前已提交、已授权字段。存在则按业务键 upsert，不存在则使镜像行退出 `is_current`。主键变化同时处理两个键。这样源事件提交乱序、删除后重建或重试不会把旧 after-image 覆盖到较新的源现态。镜像平台行 ID 保持与业务主键分离，沿用公共身份解析及内部列避让契约。

PG 在同一事务中提交镜像变化与 `pending_ack` 精确 ID 数组；只有本地提交成功后才向源端精确确认这些 ID。源确认失败后保留数组，重启先重试确认，数组清空前不读取下一批。源确认成功而本地清空失败时再次确认相同 ID 无害。两库之间没有分布式事务，不承诺网络 exactly-once。

首次安装捕获及既有事务栅栏完成后才开始扫描基线：源触发器创建完成不代表安装前已执行 DML 的未提交事务已经退出。安装器在触发器有效后取得并释放源表 EXCLUSIVE 栅栏，等待这些旧事务结束；`bootstrapFenced` 成功标记持久化后才允许启用。等待失败保留同一安装计划重试，不从未完成的 bootstrap 开始扫描。扫描期间所有日志持续积累。基线完整成功后消费全部 pending，再进入 `streaming`，不使用 `MAX(sequence)` 截止点。基线复用 0048 的 `scanId`、`last_seen_scan`、`is_current` 及稳定来源签名；可验证的旧签名沿用既有安全兼容逻辑，未扫描旧 current 行保持原部分视图语义。

API lifespan 运行专用 CDC 任务，不启用通用动作工作者。每个消费者使用固定工作空间会话、持久租约 token 与既有对象会话锁；发布前再次核验 token、启用状态和过期时间。进程重启后取得同一对象会话锁才能接管遗留 token，并可从遗留 `running` 基线批次恢复。旧任务不能发布或确认新消费者的批次。

## 授权、失效及状态含义

每批重新核验所有者身份、读取绑定版本、稳定源签名、所选字段结构、单列主键及源捕获身份和触发器定义。新增未选择列不会进入授权投影。密码轮换、源显示信息编辑不改变稳定来源签名。

源捕获丢失、禁用、generation/定义变化、所选结构漂移或授权绑定变化，会停止消费、保留数据与日志并标记 `restartRequired`；公共镜像读取沿用既有失效拒绝规则，不静默切换全量轮询。临时断线标为 `reconnecting`，保留已授权镜像并自动重连。

活动 CDC 与手动、定时全量同对象扫描互斥；修改/撤销只读绑定也必须先暂停。活动 CDC 基线不能经普通镜像取消入口取消，须先暂停 CDC。暂停后明确取消基线会要求重新建立基线。原手动全量和已有定时全量机制继续独立存在。

状态分别提供 `phase`、`enabled`、`installed`、订阅/绑定版本、`heartbeatAt`、`leaseUntil`、`workerActive`、`pendingCount`、`pendingAckCount`、`lastObservedAt` 和 `lastAppliedAt`。`lastSourceEventAt` 与 `sourcePendingAgeSeconds` 使用源触发器写入的 UTC 捕获时间，不是提交时间或提交延迟；`lastCommitAt` 和 `sourceCommitPosition` 明确为空。完整基线只证明已完成基线覆盖，当前是否健康仍看 CDC 阶段及心跳。公共读取元信息携带 `mode=cdc` 和单独 `cdc` 状态，不用基线完整冒充实时连接健康。

此方案同步当前状态，不保留每个中间版本，也不保证多行或跨表源事务在 PG 中原子可见。未确认日志不自动按年龄清理；精确确认才删除。普通 DML 触发器不捕获 TRUNCATE、绕过触发器的装载及管理员无痕篡改，相关维护后必须停止并重新建立基线。可观测的捕获缺失、禁用、重建和定义变化会被拒绝；不能宣称识别任意管理员删除日志产生的缺口。

## 部署与当前验证范围

新增 PG 增量迁移为 `data_0049_external_cdc`，前置 `data_0048_mirror_scan_visibility`；仅新增启用 RLS 的订阅表，不删除旧定义、绑定或镜像。部署应备份自己的数据库后应用明确 revision；应用迁移与源端逐对象捕获安装是两件独立操作。迁移不执行源 DDL，不自动启用任何已有工作空间。

实现阶段已完成针对新增及接入文件的静态编译、应用导入/OpenAPI 注册核对，以及 `backend/scripts/check_cdc_sink_contract.py` 的离线路由、工作空间唯一性、业务键类型及租约拒绝检查。它们不连接数据库、不登录 HTTP、不执行源 DDL，也不代替真实 DM 交付验证。真实 INSERT/UPDATE/DELETE、事务回滚、逆序提交、重启与确认重放结果须另行记录，不能把此离线检查写成真实联调成功。

随后已完成的正式 GUI 与限定合成源真实联调结果，统一见 [CDC 实测主记录](26-10-31-cdc-live-verification.md)，包括同一基线强停恢复、真实 CRUD/回滚/迟提交低 ID、暂停积压恢复及源 ACK 成功后本地 checkpoint 清理失败窗口。
