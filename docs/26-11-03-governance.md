# 多跳范围与数据治理

本轮新增可配置的分类集合、等级、用途、角色操作授权、属性返回掩码和显式降级规则。管理入口为系统管理中的数据治理，复用角色管理权限。原有页面、对象、动作白名单和行级范围仍独立校验，用途策略不能扩大这些授权。

## 迁移与兼容

增量迁移 `admin_0053_governance_policy` 的父版本为 `data_0052_source_channels`。迁移新增按本体隔离的治理策略表，启用强制 RLS，将既有范围字段加宽，并给动作执行记录新增可空的用途字段。不会删除或重写既有业务记录，降级操作主动拒绝，避免丢失已保存策略和多跳范围。

完全没有资源策略时沿用原有行为。启用资源策略后，已声明资源及其下游按实际依赖传播分类集合、最高等级和用途交集。未解析依赖默认拒绝，可能影响同一本体中尚未标记但依赖不明确的旧定义。管理员可补充真实依赖，显式确认完整性并填写依据。不能把没有解析到边视为没有依赖。

## 配置与调用

`GET /api/admin/v1/governance/policy` 返回策略版本、已发布资源目录和传播结果。`PUT` 同一路径保存完整配置，携带读取时的 `revision`，版本冲突返回 409。资源标识直接取目录中的 `id`，不要自行拼接。分类、等级和用途编码由管理员声明，等级数组从低到高排列。

配置页可编辑角色用途授权、分类集合、等级上限、操作和明文授权，也可配置资源分类、等级、允许用途、返回掩码、补充依赖及降级依据。降级必须匹配管理员事先允许的规则。生效结果页可按已保存策略核对角色、用途和操作，展开查看直接传播依据。该结果只解释用途策略，不能替代页面、对象及行级权限。

新建工作空间不必借用其他本体的系统角色。候选也包含当前本体成员表中实际存在的所有者、编辑者和查看者，编码为 `ontology:owner`、`ontology:editor` 和 `ontology:viewer`。保存校验、模拟核对和运行时使用相同主体合同，运行时再次读取该用户在当前本体的真实成员角色。服务账号仍仅使用显式绑定的角色。页面的更新角色按钮只刷新候选，不清除正在编辑的策略。

调用者通过 `X-Data-Purpose` 明确声明用途，所有业务请求仍须显式携带 `X-Ontology-Id`。浏览器顶栏仅列出当前本体角色获得的用途，切换用途会取消旧请求并重新加载页面。用途编码本身不是授权，后端仍检查当前本体角色绑定、分类、等级和操作。机器调用仍使用 Bearer API Key，密钥 scope 与白名单继续生效。

属性读取可返回空值或脱敏文字，掩码在服务端执行。筛选、排序、分组、聚合、导出和外发需要对应操作与明文授权。通用对象读取接口负责掩码，不能安全改写结果的原始 SQL 或旧业务读取接口拒绝返回掩码字段明文。已注册计算属性的底层输入列同样受限制，可能比仅检查输出别名更严格。

动作暂存时记录用途，执行时重新校验原存储用途。旧动作记录的空用途不会借用确认人的新请求用途。执行前检查动作、写入属性及外发系统和端点。远程计算函数内部来源不能靠输入输出 schema 证明，默认保留未解析；经过验证的本地纯计算函数不虚构数据来源。函数固定版本调用与显式字段参数在调用点建立依赖。

告警、命中、事件和动作运行记录中的自由文本没有足够依据做局部字符串掩码。启用策略后，来源不可确认、版本不匹配或需要掩码的记录在 SQL 计数和分页之前过滤，详情返回明确的 `GOVERNANCE_DYNAMIC_DENIED`。列表响应通过 `X-Governance-Reason` 标明历史输出过滤合同。规则执行、事件载荷筛选和真正外发前再次校验用途与明文授权，后台事件投递路由须显式配置 `data_purpose`，未声明时不会推断用途。

历史动态输出只在稳定来源版本匹配、记录创建时间严格晚于当前依赖元数据水位时复用当前策略，事件还要求绑定当前发布记录和事件定义版本。旧快照、时间相同或来源不明均不会借用当前较宽标签放行。没有稳定来源合同的其他保留动态输出也默认拒绝。这一保守边界可能隐藏本体定义变更前的记录，不修改或删除这些记录。规则去重维度的未解析来源需管理员补全，不能用显示引用冒充血缘。

## 多跳行级范围

角色与权限中的行级范围可选择最多四跳的关系路径，保存稳定关系编码与末尾属性 API 名。元数据、保存校验和编译共用一个 resolver。每跳要求同一本体、已发布对象与关系、真实受控列及本体隔离列，暂不接纳中间表关系、计算关联键或无法唯一确认的绑定。

范围编译成带独立别名的嵌套 `EXISTS`，每跳附带本体条件，比较值使用绑定参数。未知关系、缺失属性、混合本体和超过四跳均拒绝。已有单跳范围和角色之间的 OR 合并语义保留。配置取值按需读取，最多显示前 200 个，支持关键词缩小范围，保存时服务端重新验证。

## 验证边界

`python -m scripts.check_governance`、`python -m scripts.check_governance_dynamic` 与 `python -m scripts.check_relation_paths` 已通过纯内存断言，覆盖标签传播、用途与等级拒绝、降级、未知依赖、掩码及 SQL 用法、函数固定版本和局部命名域拒绝、动作用途恢复、动态来源和版本、分页前计数，以及一至四跳别名、本体条件和绑定参数。新增治理模块、resolver 和检查脚本 Ruff 通过，前端完整 `typecheck` 通过。后端模块导入通过且未启动生命周期。

这些离线检查没有访问数据库或 HTTP，没有运行全量 pytest、迁移测试或打包。

主任务另已应用0053必要增量并通过正常管理员页面验收本体8：声明Score属性用途后，未选用途被拒；选择所有者获授的verification用途后，问数返回10/40/45；撤销明文权限后，评分聚合明确拒绝。现场暴露并修复SSE未传用途头，以及流式独立数据库会话丢失用途和身份的问题。临时资源策略已恢复为空，未改变其他本体。此单账号矩阵不等于正式组织、多跳权限、机器身份及所有历史输出的全量现场验收。

首屏性能修复将经过审阅的纯定义GET与业务查询初始化分开：真人仍校验活跃账号、功能权限、当前本体成员和RLS，仅跳过无关业务绑定反射；其行授权为空并按既有row_filter拒绝。API Key、业务查询、试算、执行和带真实数据的接口不走快路径；未来如给allowlist处理器加入业务读取，必须先移出该清单。复杂SQL检查按节点身份完整遍历，不反复访问共享CTE；嵌套子查询、别名和最深业务表检查保持。
