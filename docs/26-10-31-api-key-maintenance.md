# 2026-10-31 外部系统 API 密钥维护

本轮维护对象是平台签发的 Bearer API 密钥。没有读取、展示、创建、轮换、吊销或修改任何真实密钥；没有连接数据库、外部系统或启动 worker。原工作区的其他修改保留，没有提交或打包部署。

## 已有能力和补齐内容

已有创建、名称/备注/有效期/IP 配置、用户或服务账号身份绑定、当前本体绑定、scope、动作/事件/函数白名单、限流配额、掩码列表与详情、分页调用记录、吊销和实时到期检查。创建只返回一次明文，数据库保留哈希、前缀和末四位。机器密钥不能管理自身或其他密钥。

此前名称备注/IP/期限只能在创建时填写；没有原位轮换，正常有效密钥也未显示复制配置入口。现复用现有详情和表单补齐：

| 操作 | 行为 |
| --- | --- |
| 维护配置 | 可改名称、备注、配额；scope、IP、类型白名单和有效期只可收窄。显示绑定本体，不能原位更换身份、本体或环境。 |
| 轮换密钥 | 对有效或即将过期密钥只更换凭证材料。保留编号、原授权快照、身份、本体、白名单、配额和到期时间。旧明文在轮换事务提交后失效，新明文只显示一次。 |
| 复制配置新建 | 所有状态均有入口，但只有来源明确且仅绑定当前同一本体时才自动复制。跨本体、多本体或未知来源会禁用表单和生成，显示来源/目标并要求切换来源本体或改为手动新建，避免同名编号误授不同实体。原密钥不自动变更或吊销。 |
| 吊销 | 继续使用已有审计确认；之后的新请求返回 401，不能恢复。 |

需要平滑切换时，先复制配置新建，保存新明文、由调用方验证切换，再单独吊销旧密钥。需要即时替换且可接受旧凭证立即失效时使用轮换。轮换和吊销不会取消已经完成认证的在途请求。

创建确认已修正文案：不再声称所有密钥都只能读取元数据 GET，而是按实际选定 scope 授权。当前本体编号和重新签发的授权快照语义明确显示；列表/详情不返回任何明文凭证。

跨本体复制保护也覆盖直接URL中的`from`参数；阻断时不提交任何创建请求，不把有限白名单清空成`null`。同本体复制仍需明确确认当前身份、scope、期限与新授权快照；更换本体须手动重新选择定义，不能把本体局部编号当成全局身份。

调用记录补显示后端已有的来源 IP，并将所有 2xx 标成成功，避免把事件写入等接口的 201/202 回执误标失败。

## 后端契约

- `GET /api/admin/v1/api-keys` 和详情行增加 `version`，来自现有乐观锁版本。
- 新建/复制后重新签发时，在已有主体/scope授权检查后增加当前可信本体中的编号存在性校验；仅投影动作/函数`code`、事件`code/api`，不读取或执行定义。未知或只在其他本体存在的编号返回400及白名单字段索引；`null`不限和`[]`拒绝全部均合法。维护名称备注或轮换不执行该新校验，避免历史定义已删使凭证无法维护。存量记录不回填。
- `PATCH /api/admin/v1/api-keys/{id}` 在现有策略字段上增加 `version`、`name`、`note`、`ipAllow`、`expiresAt`。页面提交版本以拒绝覆盖过期表单；已有调用方可继续省略版本。`expiresAt` 必须含时区、晚于当前安全时钟且不能晚于原到期时间；有限期不能改成永久有效。已过期密钥不能通过这个字段恢复。
- IP 白名单仍是空数组表示不限制；原有限来源不能清空或扩大网段，只能保持/收窄。不同 IP 地址族不能相互授权。
- 动作、事件和函数白名单统一为 `null` 表示当前 scope 下全部类型，`[]` 表示全部拒绝。已有有限集合只能变为其子集，不能恢复 `null` 或加入新编号。原来动作/事件 PATCH 可扩大的路径一并收紧；函数已有限制保留。删除相应 scope 后可清除不再适用的白名单。
- `POST /api/admin/v1/api-keys/{id}:rotate` 接收 `{version}`；要求 `api-keys:manage`，服务账号密钥还要求 `roles:manage`。行锁加版本检查阻止重复/过期轮换，已吊销或过期密钥拒绝。只更新哈希、掩码、更新时间（现有 ORM 自动推进版本），返回一份含 `secret` 的结果并加 `Cache-Control: no-store`、`Pragma: no-cache`。
- 配置维护和轮换写已有审计日志，仅记编号、名称、字段名/操作，不记录凭证或载荷。字段白名单拒绝直接修改 `ontologyIds`、身份或授权快照。

本轮未回填任何存量 key 的 `func_snapshot`，未改变已有本体绑定，也未改新规则 definition 的只读 `meta:read` 契约。扩大权限/来源/白名单、延期或改变绑定必须显式重新签发。

## 事件接入凭证的区别

外部事件接入推荐使用平台管理的 `events:ingest` Bearer密钥，取得本体、身份、事件类型白名单、过期/吊销、IP/配额和调用日志约束。**当前源码实际HTTP入口只有 `POST /internal/v1/events`，虽然路径含internal，但它已经接受该平台Bearer；没有独立的`/api/.../events`公共别名，不能把未实现的路径交给调用方。**

已支持的请求头与通用信封契约如下，仅为非业务示例，不是发送指令：

```text
POST /internal/v1/events
Authorization: Bearer <由平台一次签发并安全保存的凭证>
X-Ontology-Id: <该密钥明确授权的本体编号>
Content-Type: application/json
```

```json
{
  "eventId": "example-event-0001",
  "eventType": "ExternalExample",
  "occurredAt": "2026-10-31T10:00:00+08:00",
  "source": "example-system",
  "objectType": "ExampleObject",
  "objectId": "example-object-1",
  "payload": {"value": 1},
  "dedupKey": "example-source-0001",
  "traceId": "example-trace-0001"
}
```

必填字段是`eventId/eventType/occurredAt/source/objectType/objectId/payload`，`dedupKey/traceId`可省略；时间必须含时区，本体只由请求头选择，不向信封加入`ontologyId`等额外顶层键。信封最大64KiB并受嵌套/条数限制。事件编号或API名、对象类型和载荷必须符合所选本体当前接受的外部事件定义及类型白名单；同名其他本体定义不授权。接收返回`{eventId, deduped}`，表示已接收/业务去重，不表示订阅处理成功。此入口保留原生产事件语义，密钥名称/环境标签不把请求自动转换成隔离模拟事件。

同一入口还兼容部署环境配置的内部事件静态 token（`RENGU_INTERNAL_EVENT_TOKEN(S)`）。它没有平台密钥记录、个人生命周期、到期字段或密钥调用日志，不能把它当成“已在 API 密钥页面可维护”的外部凭证。其替换/撤销依赖部署方更新对应内部配置；本轮未自动迁移、更改或回读这些秘密。配置化的出站 HTTP token/签名秘密同样属于接收方/运维配置，并非平台对外签发的 Bearer key。

由授权维护者分步迁移：在平台为所选本体新建受限`events:ingest`密钥，限制事件类型、来源IP和期限；调用方保持实际`/internal/v1/events`路径与受控信封，将Authorization替换为新Bearer并显式传同一本体头；在已授权的独立环境验证权限/接收/调用日志后，再停用对应旧静态配置。该迁移不需要更改body字段，不能在路径仍无实现时切换到臆造的公共URL，也不能提前禁用旧路导致断链。停用静态配置须先核对是否仍被其他调用方使用。本轮不创建密钥、不测试发送、不更改旧配置；若后续需要独立公共命名空间，须另行实现并核验契约，而非文档冒称已支持。

## 本地验证及界限

在 `backend` 运行 `.venv/Scripts/python.exe -m scripts.check_api_key_maintenance`：使用惰性假记录/假会话和固定无效凭证 fixture，不创建引擎或连接。覆盖三类白名单的 `null`/空集合/子集语义、IP 收窄、时区和期限、禁止绑定额外字段、轮换只改凭证材料、旧哈希失效、版本冲突、过期/吊销拒绝、服务账号额外权限、返回禁缓存和审计不含明文。

前端新增 `node scripts/check-api-key-copy.mjs`，断言同单一本体允许、跨/多/未知绑定与不安全编号拒绝，并编译实际SFC；检查不发API请求。后端新增编号目录mock与PostgreSQL编译断言，确认查询只投影编号并显式过滤空间，不读载荷或执行定义。没有运行全量测试、真实数据库事务/RLS/并发认证检查或任何真实密钥操作。

主任务另在localhost只读查看实际列表、详情、调用记录和未提交表单；首次发现的跨本体复制风险由上述guard补齐。来源本体11到目标1的GUI重验已通过：来源/目标提示明确，复制未应用，整张表单与生成按钮禁用，没有创建或修改任何key。常规API重启请求被自动审批返回`blocked by policy`、未给详细原因，命令未执行，旧API仍在；本轮后端代码尚未加载，不可宣称部署已验收。

## 本轮追加：详情恢复

维护或吊销返回新版本后，较早发起、较晚返回的详情查询不再覆盖新版本；该查询的调用记录仍正常展示。详情尚在加载时完成维护或吊销，也会显示操作返回的当前记录。吊销服务账号后重新读取已打开的密钥详情，避免保留旧有效状态；确认期间切换本体则取消吊销操作。

`node scripts/check-api-key-copy.mjs` 已追加合成行与延迟 Promise 检查，覆盖上述迟到响应、调用记录保留、服务账号吊销后的详情恢复及确认期间切换本体取消，并编译实际 SFC。该检查不加载 HTTP 客户端、不调用后台、不操作真实密钥；不能替代真实事务、网络中断或部署后生命周期验收。此次仅修复前端恢复流程，后端收窄及 `null`/`[]` 语义保持原样。

主会话只读补验 `/admin/system/api-keys?ontology=1`：列表两条已吊销测试密钥，现有 `ext-trigger-retest` 详情状态与列表一致，两条调用记录及来源 IP 正常；实际视窗 2560×1440 无页面溢出，截图见[只读详情证据](evidence/api-key-readonly-detail-2k-20261031.jpg)。未点击维护、轮换、吊销、复制或创建；该只读证据不能证明迟到 GET 竞态或真实密钥生命周期已验收，独立源码复核无新发现也不等同运行验收。
