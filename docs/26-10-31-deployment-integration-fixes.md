## 源库与镜像一致性

当前实现为授权触发的有界分页全扫描加本地upsert，**不是CDC，也不是源数据库事务快照**。普通显示编辑、描述和密码轮换不再使新稳定签名失效；换源、主键或所选语义/安全映射变化仍需重新核对。每批核对所选结构，变化时中止并提示重新确认；未选择的新源列不会自动进入授权。

本轮新增必要的0048增量迁移：`last_seen_scan`、`is_current`及索引，旧行先保持可见，新行默认非当前。只有完整成功扫描的末事务，才将同源签名中未见旧行排除当前查询，物理记录保留；失败/取消不误判删除，同次恢复沿用scanId。旧complete仍需看`deletionsAligned`，删除未核对时标partial，`dataPublishedAt`单独记录完整发布时间。本机已备份后从0047升级到明确目标0048，原物理镜像行76→76；部署机仍待独立备份和应用，不能跳过改表仅换代码。

扫描期间源仍可变化；已扫行的后续更新、游标之前新增键需要下一次明确扫描。部分扫描可能混合新旧值，多表之间不承诺同一时刻一致。历史签名数据保留但不作为当前绑定提供。旧签名先精确验证再明确完整同步升级；过去已失配不伪造信任。外部动作HTTP成功也不能证明源库与镜像已经一致。

角色范围编译、动作条件和组织/属性候选读取已接入当前会话受控registry与物理列映射；无映射或歧义仍拒绝，不靠显示名称重建权限。

## 保留数据升级顺序

以下为部署方审阅后执行的步骤；本机已完成备份、0048必要增量、API重启及后续限定真实联调，均没有替部署端执行。占位符必须由部署方在本机安全替换；勿从问题报告复制实际凭据进仓库、命令记录或本文。

1. 保持通用事件worker停止；安全备份平台数据库、部署配置及`backend/.env`，保留数据源加密所需原密钥。不要重置数据库、覆盖环境文件、seed、清理投递或改写历史快照。
2. 更新同一版本的源码、前端及发布材料，核对未提交/未跟踪文件是否包含。按[镜像数据库增量升级操作单](26-10-31-mirror-database-migration.md)核对备份、依赖与实际数据库head，再应用0048及其缺失前置迁移；不import开发机dump覆盖部署数据，不重置库或seed。首次确实缺队列schema时，另按操作文档安装；不要在API启动时隐式安装。
3. 先仅启动API：`python <项目绝对路径>/backend/run_dev.py --api-only`。API自身已授权的镜像计划仍可能运行，API-only只表示没有联启事件worker；先核对原有计划配置。保持用户数据库、账号、连接、卷及历史记录。
4. 先只读核对镜像状态与运行记录，区分`processed`、`currentStored`、`complete`、数据更新时间和状态时间。需要恢复时由操作人明确选择“继续同步”或“重新同步”，不自动清空或解绑。读取授权页面可能实际连接源库，不应当作纯本地状态查询。
5. 完成镜像对象覆盖、身份唯一、授权版本、目录映射核对后，只读记录上线前事件主键高水位。用限定模式验收一条高水位后的指定单订阅新事件，核对接收端、规则命中、告警/动作、投递回执与幂等结果；多订阅事件不适用此模式。
6. 预览旧积压，逐条核查原快照、原回执、已有业务结果及前序事件，明确选择重试/补投/跳过/已接收；unknown先核查结果。完成明确处置后才恢复独立通用worker；它会消费所有工作空间符合条件的积压。

限定联合启动示例（不会启动通用sweep；高水位不得随手填0）：

```text
python <项目绝对路径>/backend/run_dev.py --with-worker --ontology <工作空间ID> --event-type <事件类型编码> --subscriber <唯一订阅名称> --after-id <只读核实的上线前事件主键高水位>
```

投递等待、重试、恢复和镜像调度操作时间已改用真实UTC，避免显式演示时钟冻结运行期限；业务事件时间与用户`.env`不改写。部署端仍需核对是否显式启用了业务演示时钟。
