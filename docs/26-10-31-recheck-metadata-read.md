# 2026-10-31 复检：机器密钥读取规则定义

针对《本体平台新版复检报告》§5.3，新增明确的只读规则定义接口。原规则详情 GET 保持原来的界面语义和 Bearer 拒绝策略；没有修改任何存量密钥、角色、账号或本体数据。

## 原因与接口

旧接口 `GET /api/ontology/v1/rules/{code}` 不在 `api_keys.METADATA_ROUTES` 白名单内，也没有声明机器调用 scope，因此包含 `meta:read` 的 Bearer 请求在认证阶段返回 403。原详情还混合草稿、最近命中数、待暂存动作数量，不能把整条接口按元数据放开。

新增：`GET /api/ontology/v1/rules/{code}/definition`。

请求沿用 `Authorization: Bearer <密钥>` 与 `X-Ontology-Id: <已授权空间编号>`。未传空间编号时沿用平台空间 1 的规则，不自动选择密钥获授权的空间。此接口也可供具有 `rules:view` 的真人会话读取；未登录请求仍走原认证。

响应为 `{release, definition}`。`release` 是当前空间最新已持久化发布记录的版本号；`definition` 只从该记录的 `snapshot.rules[code]` 读取，不从当前可变规则表重建，不合并草稿，不遍历旧发布记录寻找已被当前版本移除的规则。没有提供历史版本、草稿或执行选择参数。

出参采用独立白名单模型，保留规则编号、名称、版本、状态、所属对象类型、条件、表达式、去重/冷却、触发配置和动作暂存配置等声明字段。条件、触发器、暂存配置及映射均有固定字段模型，未知键递归丢弃。不会返回整份发布快照、外部 HTTP 认证对象、连接凭据、`runAsUserId`、确认人身份、`weekly`、草稿、命中明细、运行记录或待执行数量。表达式和映射只作为字符串读取，读取过程不编译、不回放、不执行规则或动作。

当前发布快照缺少规则、无发布记录、规则编号不匹配、版本为空或结构不能通过出参校验时，统一返回 404「规则已发布定义不存在」，不在错误详情中附带快照内容。被当前发布版本移除的规则同样返回 404。

## 权限与隔离

机器访问必须同时满足：

- 密钥有效且未吊销、未过期；绑定用户仍有效，或服务账号及其角色仍有效。
- scopes 包含 `meta:read`；`dynamic:read`、`objects:read` 单独使用均不够。
- 密钥签发时的功能快照与身份当前功能权限取交集，包含 `rules:view`。新增 scope 携带上限只有 `view`，不会携带 `rules:manage`。
- 所选空间存在、未删除，属于密钥持久化的空间允许列表，并且用户仍是成员，或服务账号角色仍绑定该空间。
- 继续通过既有 IP 白名单、配额及禁止覆盖/预览其他身份等校验。

新增入口通过现有全局 `ApiKeyGuardDep` / `OntologyGuardDep` 和本地 scope、页面依赖。会话仍通过 `bind_workspace` 绑定本体，数据库仍使用 `rengu_ontology_scoped` 与强制 RLS；新查询还显式要求 `ontology_release.ontology_id == require_ontology_id(session)`，只投影发布版本号与目标规则 JSON，不读取其他快照分段。缺少可信空间上下文时在发出查询前拒绝。

请求没有空间访问权时，沿用现有空间鉴权的 403/404；已经获授权的空间中找不到该规则时为 404，不跨空间查询或透露规则所在空间。`X-Tenant-Id` 在现平台仍是一期单租户的审计透传字段，不能作为独立多租户隔离能力；本次未扩大这一既有契约。

旧规则详情 GET、规则列表/编辑辅助信息、版本详情与运行列表没有因此成为机器元数据接口。命中等既有动态读取入口仍要求自身的 `dynamic:read` 及行级访问控制；草稿写入、发布、恢复、回放和执行权限没有变化。

**存量密钥不自动扩权。** 新代码只把 `meta:read` 可携带页面的上限增加 `rules:view`，并更新密钥管理的能力展示；不会回填 `func_snapshot`。仅有旧 `meta:read` 且快照不含 `rules` 的密钥仍会返回 403，需要通过正常授权流程重新签发、在签发时获得 `rules:view` 快照后才能读取新入口。如果存量密钥本来已因其他 scope 保存了 `rules:view` 且同时含 `meta:read`，仍按其既有快照与当前权限交集判定。本轮没有签发或修改任何实际密钥。

## 已完成的本地验证

仅执行本地纯权限函数、路由声明与序列化检查，及不连接数据库的假会话 SQL 编译检查。自检脚本为 `backend/scripts/check_rule_metadata_read.py`，运行方式为在 `backend` 目录使用现有 Python 环境执行 `python -m scripts.check_rule_metadata_read`。

- scope 到页面只携带 `rules:view`，移除当前权限或缺少原快照均不能获得访问权；manage 拒绝。
- 新接口只声明 GET、`meta:read`、`rules:view`，旧详情没有新增机器 scope；无 scope、仅动态读取、仅对象读取均不能通过新入口 scope 检查。
- 独立出参模型递归过滤模拟的隐藏认证对象、运行字段、身份及草稿，同时保留正常条件数据。
- 查询只有一次只读 SELECT，显式按空间筛选，按发布记录 ID 倒序取最新记录，仅选择版本号及单个规则 JSON。未引用命中、动作运行或草稿表。
- 无发布、缺规则、编号不匹配、未发布版本统一 404；无空间上下文不发出查询。
- 新增自检脚本通过 Ruff；五个变更 Python 文件均通过内存语法编译。

结果：上述本地检查通过。
