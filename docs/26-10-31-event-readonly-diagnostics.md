# 2026-10-31 通用事件只读运维诊断

本轮只补通用事件的异常查询与展示，不处理任何业务流程或真实环境数据。工作区已有大量未提交成果；本页只描述本轮增量。

## 本轮实做

- `GET /event-types/{type_id}/delivery-exceptions` 增加可选 `error` 精确错误码筛选，最多 128 字符，格式为大写字母开头的大写字母、数字、下划线。保留原有对象权限、状态、关键字和分页条件。
- 计数与分页使用同一筛选查询；响应 `total` 是这些条件下可见投递行总数，不是当前页条数。响应新增 `errorFilter` 回显实际应用的错误码；未传为 `null`。
- 已有 `ACTION_RELEASE_CHANGED_REQUIRES_REVIEW` 增加固定说明：“当前本体发布版本不可用或与入站绑定版本不同；须人工核查”。该码来自现有动作投递的本体发布版本保护，不能证明动作定义本身发生变化。这是只读解释，不改变状态、可重试范围或执行路径。
- 前端使用该错误码进行服务器分页筛选；选择原因后核对响应 `errorFilter`，旧接口未返回匹配值时提示服务尚不支持筛选，避免把未筛选的结果呈现为有效筛选。具体前端检查结果在下方补充。

示例契约：`delivery-exceptions?state=failed&error=ACTION_RELEASE_CHANGED_REQUIRES_REVIEW&page=1&size=10`。返回仍为原投递行列表，包含已有 `error`、`errorMessage`、`typeVersion`、`ontologyVersion`；新增顶层 `errorFilter`。这只能统计已有确切错误码记录，不能据此宣称所有版本相关失败已被分类。

## 已有功能，未重复开发

- 近期事件已有 `outcome=已去重` 筛选，支持 `24h` / `7d` 范围及服务器 `page` / `size` 分页；仓储层计数、分页使用同一结果条件。
- 运行健康已有 `dedup` 计数，来自近 7 天事件结果汇总；近期事件仍沿用既有排除未来事件、测试事件的规则。
- 异常行已有绑定的事件类型版本、本体版本和错误码；历史追加记录及结构化 `errorDetails` 沿用已有实现。

## 未做与已知缺口
