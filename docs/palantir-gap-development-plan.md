## 1. 目标

先解决源数据、镜像、对象和执行之间的不一致，再增强通用建模、复杂自动化、AI 和应用交付。每项交付须能从界面或公开 API 观察到真实行为；只增加页面、配置壳子或示例返回不算完成。

## 2. 当前基础与差距

已有：独立本体工作空间、对象和关系建模、直接保存、完整本体正式发布、指标程序、本地及远程函数、MySQL/达梦来源、镜像与 CDC、HTTP 和受控数据库动作、问数内确认执行、规则和用途治理。不要重复开发或把受限能力写成完全缺失。

## 3. 范围和约束

- 保护现有数据和工作树，不重灌、不清库、不强制覆盖；只用 rengu_ontology，不修改 auto_ontology。
- 运行时读取和操作只用前端、HTTP 或 MCP；业务请求带 X-Ontology-Id，机器请求使用 Bearer API Key。
- 动作用 Idempotency-Key，按 runId 查最终状态；结果未知只对账，不盲目重发。保留已有异常证据。
- 编码来自能力目录；变更后重新读取目录和 releases/current。不同本体、页面和版本不串用上下文。
- 单账号不加审批人；保留自动执行/人工确认策略。已删除的产品页面不因对标重新添加。
- 凭据不写前端、日志、URL、计划或仓库；外部业务写入仅对明确授权的接口和合成对象执行。
- 新增表结构时给出增量迁移、兼容与保留数据说明，不能用“会改结构”回避必要修复。
- 不运行后台全量测试、pytest、集成或迁移测试；以受影响的真实页面和业务路径验收。新增逻辑保留最小定向检查，执行状态如实记录。
- 页面实操固定 2560×1440，并关注 1920×1080 与 Chrome 102 兼容；不打包、不提交、不推送，除非用户另行要求。
- ERP、Kafka、真实预测模型及专用业务算法继续后置，不阻塞通用能力。

## 5. 首个交付：DATA-01

### 问题与目标

外部绑定 PUT 当前先要求 CDC 暂停，并在保存时无条件使订阅失效。即使来源、字段和视图唯一键完全未变，也可能要求重建基线。前端对普通表有局部跳过，但视图及其他 API 调用仍会触发；不能靠某个按钮规避后台缺陷。

目标是语义幂等：同版本、同来源、同字段集合、同唯一键的保存返回当前绑定，不更新绑定版本、不改 CDC 游标、不生成虚假修改审计。字段顺序不改变授权含义；源标识保留真实大小写，不能将不同物理表合并。

### 可见行为

```text
数据连接 → 库表 → 配置读取授权
  原样保存            → 授权未变化；现有同步保持
  CDC 开启时实际改字段 → 提示先暂停；不写入
  已暂停时实际改字段   → 新版本；明确需要核对并重新初始化
  旧版本保存          → 冲突；保留用户输入，不覆盖新绑定
```

沿用现有模态框和主题，不新增介绍横幅。错误、加载、只读和切换本体后的过期响应均保留明确行为。CLI 与新公共 API：不新增；既有 PUT 返回可向后兼容的 changed 字段。

### 需求及验收

| 需求 | 行为 | 验收 |
| --- | --- | --- |
| FR-1 | 原样或仅字段顺序变化不修改绑定和订阅 | AC-1：绑定版本、CDC 状态与基线不变，返回 changed=false |
| FR-2 | 实际变更仍受暂停、来源、列授权和视图唯一键校验约束 | AC-2：运行中拒绝实际变更；暂停后保存实际变更会标记需重建 |
| FR-3 | 旧版本不能因“看起来相同”绕过并发检查 | AC-3：旧版本请求返回版本冲突，未写入 |
| FR-4 | 前端根据服务端结果显示准确反馈 | AC-4：未变化不提示重新同步；实际变化不伪装同步已完成 |
| FR-5 | 不因请求失败、页面关闭或本体切换污染其他上下文 | AC-5：失败保留当前输入；过期响应不更新新页面 |

非功能约束：保持 HTTP API 兼容；无新增表和依赖；无源业务写入；无重建镜像、删除记录或隐式重放。已保存列顺序不因原样保存重排。

### 文件和调用链

| 文件 | 修改目的 |
| --- | --- |
| backend/app/modules/data/governed_router.py | external_save 作为共享修复点；保留授权、版本和锁，识别语义无变更 |
| backend/app/modules/data/external_cdc.py | 实操发现并修正 MySQL 重连后旧错误残留、空轮询冒充镜像写入 |
| frontend/src/pages/data/ExternalReadBindingModal.vue | 去除仅普通表生效的客户端规避，按 changed 显示结果 |
| frontend/scripts/check-external-binding-save.mjs（新增） | 最小前端检查：无变更反馈、实际变更、错误和上下文边界 |
| docs/palantir-gap-development-plan.md | 维护范围、状态与证据 |

所有外部绑定写入调用先通过 rg 查找。复用 external_mirror.signature 的既有稳定语义，不更换已保存签名算法；CDC require_paused 继续保护实际变更。原样保存仍验证当前对象与源映射，不复活撤销或失效授权。

实施步骤：先记录相关文件当前内容；修改共享保存路径；调整前端反馈；保留定向检查；从当前本体合成表/视图执行实际授权保存并核对同步状态；记录仍未覆盖的来源和并发场景。

不采用“忽略所有绑定版本”“保存时自动重建 CDC”“自动放开所有列”或“清空重导”：这些方式会丢失并发保护、影响原数据或扩大授权。

## 6. 后续阶段设计门槛

- DATA-02：先复用已有镜像/CDC 状态，公开绑定版本和水位依据；未读取源最新位置时不显示“已追平”。诊断不能要求直连源库才能打开页面。
- DATA-03：明确主对象身份和基数，先支持可验证的一对一补充及一对多聚合，不直接开放任意 SQL；组合字段需要可追溯来源和类型。
- RUN-01/02：定义条件说明与可执行条件分开；统一入口再次读取并校验当前状态，所有写入路径必须完成调用清单。状态机不是展示图的附属逻辑。
- FLOW-01/02：复用动作记录、outbox 和任务持久化；先完成有界串行、分支、参数传递、失败停止，再增加并行。业务补偿需明确配置，不能把未知结果当失败重试。
- AI-01/02：保存结构化约束与版本依据；只评受影响问题族，保留预期结果，覆盖时间、状态、否定、对象编号、跨本体及多轮改写。
- BUILD-01/02：先扩展现有定义修改合同，生成差异和引用校验；最终由现有保存 API 持久化，不另建绕过权限的 AI 写入口。
- GOV-01/TRACE-01：未知依赖不假定无敏感来源；记录来源版本和运行输入，避免图上有边但无法解释真实执行。
- RELEASE-01/DELIVERY-01：先确定配置与运行数据分界，所有新增迁移附保留记录的升级说明；凭据只导出缺项，不导出明文。
- OPS-01：对受影响页面测量，不能以全站重拍或全量后台测试代替实际修复结果。

## 7. 验证与交付

每项记录：修改文件、可复现页面路径、输入和实际结果、失败分支、是否涉及迁移及未验收边界。未运行的检查不能记“通过”。

首个交付只检查变更路径，不跑后台测试。必要前端 typecheck 与最小组件检查允许执行；真实操作使用正常登录的固定 2K 浏览器，限定合成本体，禁止对已有 UNKNOWN 动作重发。

若需要服务重启，使用本项目既有启动配置；不额外恢复其他本体的动作/事件消费。结构迁移与源捕获安装另行记录实际影响，不能悄悄执行。
