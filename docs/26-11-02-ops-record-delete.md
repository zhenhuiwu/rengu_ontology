# 动作与告警删除入口（2026-11-02）

## 前端合同

动作中心与告警处理详情头新增“删除”。入口仅在真实接口模式出现，依据详情 `can.delete` 和 `can.reasons.delete` 展示可用性与禁用原因；历史版本、身份预览等只读态继续禁用。后端未返回版本或删除能力时安全禁用，不凭前端状态自行放行。

- `DELETE /action-runs/{id}?lockVersion=N` → 204。
- `DELETE /alerts/{id}?lockVersion=N` → 204。

两者均经原动态 API 上下文发送，不新增权限通道。危险确认明确显示记录编号、状态与影响，需要勾选确认。确认前固定 ID、版本、上下文；确认期间换记录、换上下文或版本改变不发送删除。成功后读取真实列表，清除被删详情、URL 选择和固定选中；末页总数减少时回到新的最后一页。告警同时清除该条勾选缓存并重新读取分面计数。失败保留当前记录并显示后端具体错误，不用本地 filter 冒充删除。

## 后端约束与数据边界

根据后端 owner 确认合同，动作只允许成功、失败、已撤回、已对账终态，且没有队列、执行占用或未完成对账；告警仅允许已解决或已忽略，且无活动关联动作。接口执行时再次核对权限、版本和关联状态，前端仅展示服务端能力。

后端以 `deleted_at/deleted_by` 保留必要记录，列表不再展示；执行日志、外部 call、canonical/幂等信息保留，不提供恢复入口。删除不撤销已产生业务结果、不级联删除关联动作、事件或业务对象，独立审计保留。后端新迁移的审核、应用与 API 重载由主会话负责，前端 agent 未应用迁移或删除记录。

## 迁移与部署

`dynamic_0050_record_deletion` 为动作和告警分别增加 nullable `deleted_at`、`deleted_by`，共四列。本机已在完整备份后应用一次；没有运行降级或恢复测试，不能据此宣称远端部署已验证。

远端先完整备份目标库，确认部署配置指向该目标，然后在后端环境运行 `alembic upgrade head`，成功后正常重启 API。前后端应配套部署；旧后端缺少删除能力或版本字段时，新增按钮保持禁用。迁移本身不删除既有业务记录，不需要启动 worker 或消费队列。

本功能是终态记录的可见性删除：后端再次核对权限、版本、在途执行与关联约束；删除后当前列表、详情和统计不再展示该记录，不提供恢复 UI。必要审计、执行日志、canonical 和幂等信息仍保留，删除不会使旧幂等请求重新执行。目标部署的验证应另用经授权的合成记录进行；本机限定真实验收见下节。
