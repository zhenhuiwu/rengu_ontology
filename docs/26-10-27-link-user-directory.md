# 关系建模与用户目录收尾（2026-10-27）

## 静态契约

- 关系编辑可选择源、目标对象及其真实属性。`GET /api/ontology/v1/link-types/catalog` 返回当前本体的对象和轻量属性目录；指定 `crId`、`linkId` 时叠加同一变更单已保存的新对象与属性。历史模式仅取所选快照，不混入当前定义。
- 关系保存沿用变更单审核发布流程。V3 与发布写回共用端点、属性及类型校验；`int` 与 `integer` 兼容。多对多选择本体内中间对象，已有中间表可原样保留。同单对象定义、属性先于关系写回；未验证实际发布。
- `GET /api/admin/v1/depts` 和 `/users/options` 的部门候选来自实际组织及已登记用户部门。新部门可明确输入，创建、更新、导入共用非空、128字及字符校验。真实新建不预选部门、主角色，CSV 模板仅含表头。
- 新建、导入及实际更改主角色需要 `users:manage` 与 `roles:manage`；主角色不变的资料编辑仍按用户管理权限执行。`canAssignRole` 控制界面能力，服务端独立鉴权。主角色改变只替换旧主角色成员，保留额外角色和本体授权；资料编辑不自动恢复已撤销的角色。

## 独立码表续补

- `static_0021`（前序 `quality_0020`）仅放宽 `dimension.object_id` 的非空约束，保留既有记录、外键、索引及 RLS。主代理已在完整备份后向 `rengu_ontology` 增量应用；未验证降级或恢复。降级遇到独立码表时由数据库拒绝非空约束，不删除或重绑数据。
- “维度”仍须选择当前本体的真实来源对象；“码表”可不绑定对象，但不能夹带来源属性或源列。显式填写无效对象仍报错，不静默转为独立码表。CR V4、发布写回与快照恢复共用来源规则，恢复同时还原类型和来源绑定。写回直接更新关系对象及来源显示名，避免同一事务即时快照读取旧来源。
- 真实编辑器选“码表”后来源对象可留空、可清除；无来源时禁用来源属性，可继续维护层级。保存到既有 CR 后，取值、同义词和说法映射继续使用原维护流程。目录及详情对空来源返回 `object: ''`，展示“独立码表”，不补零售对象；真实目录默认10条后台分页。
- 独立码表保留元数据匹配能力，不进入指标“允许维度”候选，也不进入问数的 SQL 分组、筛选候选。问数目录当前与历史均依据各自定义中的来源绑定过滤，并阻止指标 `dimNames` 把独立码表或其层级名称重新带回；绑定维度的同名候选及原有合法维度保持兼容。问数 SQL 提示原有对象内连接也自然排除空来源。
- 可选 `backend/scripts/check_standalone_code_tables.py` 仅留下纯内存断言，覆盖独立码表、维度缺来源、悬空来源、残留属性/源列及问数候选过滤；未执行，不接数据库、HTTP 或外部模型。仅做 Python AST、前端类型和差异空白检查，未创建码表/取值/CR 样例，未实际发布或回滚。
- 前端查看路线：`/build/ontology/dimensions?ontology=2` → “新建维度” → 选择创建/加入变更单入口 → 定义表单选“码表”。来源对象不再必填，可填写名称、API 名、负责人及层级；切回“维度”则恢复来源必填。验收仅查看表单，不保存示例记录或发布旧 CR。真实维护写入与恢复尚待业务数据使用时验证。
