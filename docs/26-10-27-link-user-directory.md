# 关系建模与用户目录收尾（2026-10-27）

## 静态契约

- 关系编辑可选择源、目标对象及其真实属性。`GET /api/ontology/v1/link-types/catalog` 返回当前本体的对象和轻量属性目录；指定 `crId`、`linkId` 时叠加同一变更单已保存的新对象与属性。历史模式仅取所选快照，不混入当前定义。
- 关系保存沿用变更单审核发布流程。V3 与发布写回共用端点、属性及类型校验；`int` 与 `integer` 兼容。多对多选择本体内中间对象，已有中间表可原样保留。同单对象定义、属性先于关系写回；未验证实际发布。
- `GET /api/admin/v1/depts` 和 `/users/options` 的部门候选来自实际组织及已登记用户部门。新部门可明确输入，创建、更新、导入共用非空、128字及字符校验。真实新建不预选部门、主角色，CSV 模板仅含表头。
- 新建、导入及实际更改主角色需要 `users:manage` 与 `roles:manage`；主角色不变的资料编辑仍按用户管理权限执行。`canAssignRole` 控制界面能力，服务端独立鉴权。主角色改变只替换旧主角色成员，保留额外角色和本体授权；资料编辑不自动恢复已撤销的角色。
