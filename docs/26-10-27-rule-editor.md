# 真实规则编辑器

2026-10-27。页面沿用现有 Ant Design 与主题tokens；不添加依赖，不修改旧示例定义和值，不创建验收用告警、动作或调度记录。

## 入口

构建区 → 规则与自动化 → 发起变更或继续已有草稿。仅草稿可编辑；已发布、审核中、历史版本及权限预览保持只读。仍通过原变更单 `PUT /rules/{id}/draft` 保存，沿用CR乐观锁、审核、发布链，草稿不会启动真实规则。

「条件」支持添加、编辑、删除与且/或组合；对象属性和所选事件载荷均从真实 `/rules/meta` 选择精确API绑定，支持字段值、距该时间小时数及分钟数。指标从真实目录选择，必须显式选择口径版本、日/周时间桶与当前值/上期值/周环比。只显示名称的旧条件保留为原表达式；编辑时必须重新明确绑定，避免从旧中文说明猜测执行含义。

结构化条件交由后台编译；表达式也可显式采用手写内容。再次编辑条件或逻辑会清除手写覆盖，保存后以新条件生成真实表达式。对象、去重键、冷却时间可在同页编辑。去重键保留明确文本格式，不自动补猜业务维度。

「触发方式」可选择定时或事件，编辑五段cron、时区、重启补偿范围、启用状态、订阅事件及过滤、计划说明。保存时后台固定真实本人为运行身份。新规则默认停用；旧事件规则缺少enabled时按原通道语义显示启用，显式关闭后发布才禁用。定时规则只有明确启用并正式发布后才进入新调度链。

「定时运行」读取 `GET /rules/{id}/runs?page=1&size=10`，真实后台分页与展开详情，显示计划时间、原规则版本、状态、候选/已计算/无法计算/告警/去重及实际动作状态。无记录显示真实空态，不补造旧历史。

## 保存与状态

只对实际编辑的定义字段传patch；原autoStage/thresholds保存接口保留。后台验证或版本冲突显示真实错误并保留输入。切换用户清空旧定义、目录与输入；选择新规则清空旧详情、错误及运行展示，读请求和保存请求都校验上下文与选择序号，迟到结果不能覆盖新页面。
