## 接口与命令变化

规则定义的机器入口是 `GET /api/ontology/v1/rules/{code}/definition`，返回 `{release, definition}`。`GET /rules/{code}`仍保留UI混合详情语义，对机器密钥不因本轮而开放。存量 `meta:read` 密钥若原快照没有 `rules:view`，新入口仍403；需通过正常授权流程**显式重新签发**，本轮不回填快照、不修改原本体绑定。

密钥管理仍在 `/api/admin/v1/api-keys`。详情行增加`version`；PATCH可维护名称/备注及收窄配置，页面提交版本防止覆盖旧表单；新增 `POST /api-keys/{id}:rotate`，必须提供当前版本。`null`类型白名单表示不限，`[]`表示全部拒绝；IP白名单的空数组则表示不限，已有有限来源不能清空。三类类型白名单统一禁止原位扩大。

创建时只读校验动作/函数编号及事件编号或API名是否存在于当前可信本体，未知编号400并给字段索引；不执行定义，不改变存量key。此校验仅用于新签发，不让历史已删定义阻断名称备注维护或轮换。复制来源与目标必须是同一明确单本体；跨本体请手动新建并重新选择定义，不能沿用另一空间的白名单编号。

外部事件接入使用已实际支持的 `POST /internal/v1/events` 加平台管理的`events:ingest` Bearer和授权本体头。该名称不表示免鉴权；当前没有独立公共命名空间别名。由旧静态token迁移时保留同一路径和兼容body，验证后再显式停用对应旧配置，本轮不操作任何token。通用请求契约见[密钥维护说明](26-10-31-api-key-maintenance.md)。

演示库显式使用 `python -m app.cli seed --demo [--dry-run] [-m 模块]`；生产拒绝demo。`seed --dry-run`会试写后回滚，不是存量只读审计。空白首次安装使用 `python -m app.cli system-init --database 数据库名`，默认只读，审阅后仅首次安装可显式加`--apply`。已有业务系统不得靠重新seed修复账号或权限。

`dynamic_0024`的表结构/RLS/授权保持原有顺序；未来运行时只有精确指定 `alembic -x demo_seed=true upgrade head` 才导入演示模板。正常生产 `alembic upgrade head` 不导入。已经应用24的库不会重跑、修改或清理旧模板；downgrade拒绝删除整个模板表。显式demo loader正常登记模板JSON，不执行场景。

## 给目标维护AI的发布顺序

以下为交接步骤，本轮没有替目标环境执行：

1. 核对目标源码/镜像版本和[最终SHA256清单](26-10-31-recheck-sha256.json)。清单是相关文件的完整工作树摘要，**不是独立补丁包或完整依赖清单**。当前有大量未提交/未追踪文件，不能只用旧Git提交或`git archive`假定已包含新模块；由维护者审阅完整源码后准备一致的发布材料。不要打包`.env`、凭据、日志或数据库备份。
2. 在授权范围内备份平台库、审阅当前迁移到head的增量，安全配置原有连接和加密材料，不输出连接串/密钥。保持事件worker停止，避免部署过程消费积压；不要重置数据库或用开发dump覆盖业务库。
3. 在独立验收环境安装锁定依赖（backend按`uv.lock`，frontend按lockfile），先运行下列离线检查。构建前后端必须来自同一份受审阅源码；本轮没有自动push或打包。
4. 部署方确认备份和迁移范围后，在backend核对`uv run alembic current`，再按正常升级流程执行`uv run alembic upgrade head`；生产不加`-x demo_seed=true`。已有24的库保留原记录，不手改版本号重跑历史迁移，也不使用降级删表回退数据。
5. 只有首次安装的空白库才执行`system-init --database 数据库名`审阅计划，确认后再`--apply`；既有用户/业务定义被保护性拒绝时改走正常管理，不绕过守卫。存量审计仅使用`python scripts/audit_seed_events.py --ontology 已授权空间编号 --database 数据库名`，报告不构成删除白名单。
6. 运行前端正常构建，按现有服务管理方式加载新API与前端。先保持worker关闭，只读查看健康状态、会话、密钥列表/维护表单及规则definition；用目标方已授权空间验证跨空间/缺scope/缺快照拒绝。不要为验收自动创建、轮换、扩权或撤销真实密钥；需要重签时由授权管理者显式操作并妥善保存一次明文。
7. 生产队列消费及历史处置单独审批/授权：先按空间、错误、年龄只读导出候选并核对业务结果、顺序、幂等与引用；不得按名称或`is_seed`批量删除，不自动retry/skip。报告涉及的业务规则、动作和外部系统操作不在本交接执行范围。
